# K0.7-P4a — Protection des structures critiques du noyau : audit et conception

**Statut :** conception P4a ; P4b (séparation, section 11) ; P4c (prototype de passage, `K0.7-P4c-controlled-writes.md`) ; **P4d (scellement de `kro_idt`, `kro_handlers` et `kro_vmm`, `K0.7-P4d-sealed-structures.md`)**. Les tables de pages restent inscriptibles (P4e).
**Base :** commit `c0eeb9e`, branche `claude/k0.7-hardening` ; `main` inchangé (`95b9cb5`) ; aucune PR ouverte.
**Méthode :**
- adresses relevées par `nm` et `readelf` sur les images construites ;
- droits **effectifs** relevés par le moniteur QEMU (`info tlb`, `xp`) ;
- recensement des écrivains dans le code ;
- **prototype jetable**, construit dans une copie isolée puis supprimé. Ses résultats sont signalés « (prototype) ».

**Rappel du risque P4** (`K0.7-M2.5-writable-aliases.md`, chemin P4) : les tables de pages et d'autres structures critiques sont inscriptibles par la projection d'identité. Une seule écriture parasite du noyau suffit pour réécrire une PTE (rendre `.text` inscriptible, projeter une garde, poser le bit utilisateur) et donc contourner toutes les protections de M2 et de R1.

## 1. Carte des structures critiques

En K0, toute la RAM gérée est projetée en identité : **adresse virtuelle = adresse physique**. Sauf indication contraire, chaque page ci-dessous est projetée en **`rw`, superviseur**. Le moniteur QEMU le confirme pour le répertoire et les tables.

**Constat de disposition :** la page `0x109000` contient **à la fois** la GDT, les deux TSS, l'IDT, les tables de pointeurs de gestionnaires, les racines du VMM, `g_bootinfo`, `g_in_panic` **et** les compteurs `g_exc_depth` et `g_irq_depth`, écrits à chaque interruption. **Aucune protection par page n'est possible sans séparation préalable.** La séparation est donc un prérequis (stratégie C).

### 1.2 Autres surfaces

- **Mémoire basse** (`0x1000`-`0xFFFFF`, dont l'IVT et la BDA) : rw. Elle n'est pas utilisée en mode protégé, mais reste inscriptible (hors du périmètre de P4).
- **Pointeurs de fonctions** dans `g_handlers` et `g_irq_handlers` : les modifier détourne une interruption **aussi sûrement que l'IDT**. Ils doivent être protégés en même temps qu'elle.

## 2. Matrice des écritures légitimes

**Légende :**
- **I** : initialisation seulement (avant la fin de `kmain`) ;
- **R** : exécution (après le démarrage) ;
- **CPU** : écriture implicite du processeur.

| Structure | Écrivains logiciels | Écritures du CPU | Pourrait passer en lecture seule après l'initialisation ? |
|---|---|---|---|
| Répertoire de pages | `paging_init` (I) ; `get_table` (R : nouvelle PDE lors d'un `vmm_map` dans une région sans table) | bit A, sur l'adresse **physique** | oui, **si** les écritures R passent par un chemin contrôlé |
| Tables de pages | `paging_init` (I) ; `map_page`, `vmm_unmap` (R) | bits A et D, sur l'adresse **physique** | oui, avec la même condition |
| GDT | `gdt_init`, `gdt_set` (I) ; `ltr` pose le bit « occupé » (I) | **bit « occupé » du TSS #DF lors de la commutation de tâche (R, à la #DF)** | **non** (prototype : triple fault) |
| TSS principal | `gdt_init` (I) | **sauvegarde de l'état de la tâche interrompue (R, à la #DF)** | **non** |
| TSS #DF | `gdt_init` (I) ; `gdt_set_double_fault_cr3` (I, dans `paging_init`) | champ de lien vers la tâche précédente (R, à la #DF) | **non** |
| IDT | `idt_init`, `idt_set` (I) ; `idt_set_present` depuis `irq_register` (I : PIT, clavier) ; modes de test `df`, `dfsentinel`, `dfguard` (R, image de test) | **aucune** (lecture seule par le CPU) | **oui** (prototype) |
| `g_handlers` | `interrupt_register` et `interrupt_unregister` (I : #PF ; **R dans les autotests**, `test_cpu`, `test=nested`) | aucune | oui, avec une fenêtre pour les tests |
| `g_irq_handlers` | `irq_register` et `irq_unregister` (I) | aucune | oui |
| `g_pd`, `g_idmap_top` | `paging_init` (I) | aucune | oui |
| `g_tables` | `get_table` (R) | aucune | non sans fenêtre (compteur) |
| `g_exc_depth`, `g_irq_depth` | chaque exception et IRQ (R) | aucune | **non** (chauds) |
| `g_in_panic` | `panic_at` (R) | aucune | non |
| `g_bootinfo`, `g_memmap` | initialisation (I) | aucune | oui |
| `g_pmm`, `g_meta` | chaque allocation, libération, référence (R) | aucune | **non** (chauds) |

## 3. Expériences (prototype jetable, copie isolée, supprimée)

Dans le prototype :
- GDT et TSS dans une page dédiée (`0x118000`), IDT dans une autre (`0x119000`) ;
- un paramètre `seal=` retire `PTE_WRITE` de la projection d'identité, après l'initialisation et avant les autotests.

| Expérience | Résultat |
|---|---|
| `test=df` (référence) | statut 37, double faute traitée |
| **`test=df seal=gdt`** (GDT et TSS en lecture seule) | **triple fault** ; la #DF ne peut pas être livrée : le CPU doit écrire dans la GDT et le TSS lors de la commutation de tâche |
| `test=stack seal=gdt` | **triple fault** |
| `test seal=idt` | **571 vérifications, 0 échec** : l'IDT n'est jamais écrite après l'initialisation dans les autotests |
| `test=ud seal=idt` | panique normale (statut 37) : le CPU lit l'IDT sans problème |
| `test=df seal=idt` | panique « protection violation » à `0x11905d` : le **mode de test** écrit l'IDT (`idt_set_present`) |
| `seal=pt`, première version | **ma propre boucle a fauté** : toutes les PTE des tables se trouvent dans la **première** table (`0x194000`, cadres sous 4 MiB). Une fois celle-ci scellée, plus aucune mise à jour n'est possible par l'identité : c'est un constat de conception en soi |
| `seal=pt`, ordre corrigé (première table scellée en dernier) | **production : démarrage complet**, horloge et clavier actifs. Une lecture d'une page jamais touchée (`0x07000000`) réussit, et son **bit A est posé par le CPU** alors que sa table est en lecture seule dans l'identité ; la page voisine reste sans A. **Les mises à jour A et D du CPU ne dépendent pas des droits de l'identité.** |
| `test seal=pt` | première écriture logicielle de PTE (`vmm_map` des autotests) : #PF code 3 (protection, écriture), comme attendu |

## 4. Chemins de corruption possibles

| # | Cible | Effet d'une écriture parasite | Gravité |
|---|---|---|---|
| K-PT | PTE ou PDE | n'importe quelle projection : `.text` inscriptible, garde projetée, bit U, alias de n'importe quel cadre ; **contourne E1 à E5 et R1** | **critique** |
| K-IDT | porte IDT | détournement d'une interruption vers une adresse arbitraire | critique |
| K-H | `g_handlers`, `g_irq_handlers` | idem, par un pointeur de fonction | critique |
| K-VR | `g_pd`, `g_idmap_top` | le VMM écrit dans un faux répertoire ; `vmm_unmap` cesse de protéger l'identité | élevée |
| K-GDT | descripteurs | base, limite ou DPL modifiés, puis faute ou exécution détournée au prochain chargement de segment | élevée |
| K-TSS | `g_tss_df` (EIP, ESP, CR3) | détournement du chemin de double faute | élevée |
| K-PMM | `g_meta`, `g_pmm` (y compris le pointeur `meta`) | cadre noyau marqué libre puis redistribué ; références faussées (retour de E5) | élevée |
| K-FL | `g_exc_depth`, `g_in_panic` | désactive la détection des exceptions imbriquées ou des paniques récursives | moyenne |

## 5. Stratégies comparées

| | A. Lecture seule définitive après l'initialisation | B. Fenêtre d'écriture temporaire | C. Séparation physique (sections dédiées) | D. Projections virtuelles dédiées aux mises à jour |
|---|---|---|---|---|
| Principe | sceller des pages, plus aucune écriture | lecture seule en permanence ; écriture seulement dans une fonction de passage contrôlée, interruptions masquées. Deux variantes : **B1**, désactivation temporaire de CR0.WP ; **B2**, bascule du bit W de la page | ranger les structures par catégorie de mutabilité dans des pages distinctes | identité en lecture seule, et une adresse « fenêtre » (fente) projetée temporairement en écriture sur le cadre à modifier, ou une projection récursive |
| S'applique à | IDT, gestionnaires, racines du VMM, `bootinfo`, `memmap` | tables de pages, répertoire, IDT et gestionnaires (enregistrements tardifs, tests) | **prérequis** de A, B et D | tables de pages |
| Alias inscriptible | aucun | **B1 : aucun** ; B2 : la PTE de la page elle-même doit être modifiable, donc on revient au problème des tables | aucun | **la table qui contient la fente** doit rester modifiable : alias résiduel d'**une** page, à adresse fixe ; une projection récursive en écriture serait un alias permanent de **toutes** les tables (refusé) |
| TLB | `invlpg` au scellement | B1 : aucun (les droits ne changent pas) ; B2 : deux `invlpg` par écriture | — | deux `invlpg` par écriture (ouverture, fermeture) |
| Récursion du VMM | aucune | aucune (B1) | — | modifier la fente demande d'écrire dans une table, d'où un amorçage délicat |
| Faute pendant la mise à jour | sans objet | B1 : une #PF dans la fenêtre s'exécute avec WP = 0, puis panique ; la fenêtre ne doit contenir **que** l'écriture validée | — | #PF sur la fente, puis panique |
| Interruptions | — | masquées pendant la fenêtre (monoprocesseur) ; une NMI s'exécuterait avec WP = 0 (elle mène à une panique) | — | masquées |
| Mémoire | aucune | aucune | quelques pages de remplissage (alignement) | au moins une table pour la fente, et une adresse virtuelle réservée |
| Faible RAM | sans effet | sans effet | quelques pages | une table de plus |
| Risque principal | un écrivain oublié provoque une #PF, donc une panique (échec **sûr**, détecté par les tests) | B1 : **pendant la fenêtre, toutes les pages en lecture seule sont inscriptibles** pour le code de la fenêtre ; d'où l'exigence d'une **validation stricte de la cible** avant d'abaisser WP | erreur de disposition, rattrapée par les assertions du linker et `check_elf.sh` (comme en R1f-1) | complexité ; alias résiduel d'une page |

**Ce qui ne peut pas être protégé avec le mécanisme actuel de double faute :** la GDT et les deux TSS. Le CPU y écrit pendant la commutation de tâche (prototype : triple fault). Les protéger demanderait de ne plus traiter la #DF par une porte de tâche (refonte, à étudier avec x86-64, où la porte de tâche n'existe plus et où l'IST la remplace).

**Ce qui ne peut pas être protégé sans coût permanent :** `g_meta`, `g_pmm`, `g_exc_depth`, `g_irq_depth` et `g_in_panic`, écrits en permanence. Seules des **vérifications d'intégrité** sont envisageables (`pmm_core_check` périodique, valeur de contrôle) : elles détectent, sans empêcher.

## 6. Dépendances techniques

1. **Séparation (C) d'abord :** tant que la page `0x109000` mélange l'IDT et les compteurs chauds, rien ne peut être scellé.
2. **Tables de pages :** identifier les cadres `FRAME_PAGETABLE` (le type existe depuis M2.3).
   - `paging_init` alloue les tables **pendant** la boucle d'identité : il faut une seconde passe, avant l'activation de la pagination, pour retirer `PTE_WRITE` de leur projection d'identité.
   - Une table allouée plus tard par `get_table` est d'abord un cadre libre, projeté en `rw`. Elle doit être remise à zéro, puis passée en lecture seule **avant** d'être reliée au répertoire.
3. **Toutes les PTE des tables sont dans la première table** (cadres sous 4 MiB) : l'ordre des mises à jour compte (constat du prototype).
4. **Les bits A et D sont écrits par le CPU sur l'adresse physique :** lecture seule compatible (prototype).
5. **Les autotests lisent les tables par l'identité** (`raw_pte`, `pte_of`) : une identité en **lecture seule** (et non retirée) les préserve.
6. **Les enregistrements tardifs** (`interrupt_register` des autotests, `idt_set_present` des modes de test) doivent passer par la fonction de passage, ou avoir lieu avant le scellement.

## 7. Risques de régression

| Risque | Parade prévue |
|---|---|
| Un écrivain légitime oublié : #PF, puis panique | le banc complet (39 cas, 571 vérifications) et le prototype `seal=idt` montrent qu'il n'y en a aucun pour l'IDT pendant les autotests ; mutations pour chaque scellement |
| Double faute cassée (triple fault) si la GDT ou les TSS sont scellés par erreur | GDT et TSS **exclus** du scellement ; test `exc_df` et `stack_overflow` à chaque étape |
| Fonction de passage utilisée pour écrire hors des cibles autorisées | validation obligatoire (cible dans un cadre `FRAME_PAGETABLE` ou dans la section scellée, alignement, taille), avec un test négatif et une mutation qui retire la validation |
| E1 à E5 | inchangés ; leurs autotests à chaque étape |
| Gardes R1, `.text` et `.rodata` | inchangés ; `info mem` à chaque étape |
| Faible RAM | B1 et C : au plus quelques pages ; mesurer à 1 792 KiB |
| Reproductibilité | aucune source de variabilité ; `make test-repro` |

## 8. Recommandation

1. **C, puis A** pour l'IDT, `g_handlers`, `g_irq_handlers`, `g_pd`, `g_idmap_top`, `g_bootinfo` et `g_memmap` : une section dédiée, scellée en lecture seule à la fin de l'initialisation. C'est l'effet le plus fort pour le coût le plus faible : les pointeurs de fonctions et les vecteurs ne peuvent plus être détournés par une écriture parasite. L'échec est **sûr** : une écriture oubliée produit une #PF, donc une panique.
2. **B1, fonction de passage avec désactivation temporaire de CR0.WP**, pour les tables de pages et les rares écritures tardives des structures scellées :
   - **aucun alias inscriptible**, aucune table ni adresse virtuelle supplémentaire, aucune bascule de TLB ;
   - la fenêtre se limite à **une** fonction auditée : interruptions masquées, **validation de la cible** (type `FRAME_PAGETABLE`, ou appartenance à la section scellée), écriture d'un seul mot, puis restauration de WP ;
   - elle convient à un monoprocesseur en K0.
   
   La variante D (fente de projection) est écartée pour K0 : elle laisse un alias résiduel et demande un amorçage plus complexe, pour un bénéfice moindre.
3. **GDT et TSS restent inscriptibles.** C'est une limite assumée, imposée par la porte de tâche de la #DF (mesurée). Ils iront dans leur **propre** page (C), pour qu'un débordement d'un objet voisin ne les atteigne plus par contiguïté.
4. **PMM et compteurs chauds** : inscriptibles. Une vérification d'intégrité périodique peut être envisagée plus tard (détection seulement).

**P4 sera réduit, pas éliminé.** Même après P4e, du code ring 0 peut désactiver CR0.WP (P5), et la GDT, les TSS et le PMM restent modifiables. L'objectif est de supprimer les **alias inscriptibles permanents** des tables de pages, de l'IDT et des pointeurs de gestionnaires, pas de défendre le noyau contre lui-même.

### 11.2 Mise en œuvre

- **`compiler.h` :** `SAMOS_SECTION(name)`. Le nom doit commencer par `.bss.`, ce qui donne une section NOBITS. Un autre nom donnerait PROGBITS (constat de R1e).
- **Objets placés :**
  - `.bss.p4_cpu` : `g_gdt`, `g_tss_main`, `g_tss_df` ;
  - `.bss.p4_idt` : `g_idt` ;
  - `.bss.p4_handlers` : `g_handlers`, `g_irq_handlers` ;
  - `.bss.p4_vmm` : `g_pd`, `g_idmap_top`.
- **`linker.ld` :** les quatre pages sont rangées **en tête de `.bss`**, avant la règle générale `*(.bss .bss.*)` (`ld` range une section dans la première règle qui la désigne). Chacune est complétée jusqu'à la page suivante.
  - Symboles : `__kcpu_start`/`__kcpu_end`, `__kro_idt_start`/`__kro_idt_end`, `__kro_handlers_start`/`__kro_handlers_end`, `__kro_vmm_start`/`__kro_vmm_end`.
  - **Les pages restent dans la plage remise à zéro par `_start`** (`[__bss_start, __bss_end)`) : aucune dépendance au remplissage par le chargeur (leçon de F1).
- **10 assertions du linker :** `kcpu` en tête de `.bss` ; chaque page alignée ; chaque page de **4 096 octets exactement**, donc un contenu plus grand échoue ; chaque page contiguë à la précédente ; la dernière avant `__bss_end`.

| `kro_vmm` | `0x10c000` | `0x11b000` | `g_idmap_top`, `g_pd` | rw (inchangé) |
| `.bss` ordinaire | à partir de `0x10d000` | à partir de `0x11c000` | `g_exc_depth`, `g_irq_depth`, `g_tables`, `g_pmm`, `g_meta`, ... | rw |

Répercussions en production :
- `.stacks` passe à `0x18e000`, avec la garde S2 `0x18e000`, S2 `0x18f000`, la garde basse S1 `0x190000`, S1 `0x191000`-`0x194fff` et la garde haute `0x195000` ;
- CR3 passe à `0x196000`.

Les trois gardes restent absentes (`info mem`).

### 11.4 Consommation mémoire

| | Avant (`c0601658`) | Après |
|---|---|---|
| Production : fichier ELF | 147 460 | 147 440 |
| Production : `.bss` | 531 112 | 544 088 |
| Production : `__kernel_end` | `0x193000` | `0x196000` (**+12 KiB réservés**) |
| Production : `memsz` du segment `data` | `0x8b000` | `0x8e000` |
| Démarrage à faible RAM | normal dès 1 792 KiB | **inchangé** : normal à 1 792 KiB, `ENOMEM` déterministe à 1 728 KiB |

Les quatre pages contiennent environ 3,6 KiB de données pour 16 KiB réservés. C'est le prix d'une protection par page.

### 11.5 Vérifications ajoutées

- **`check_elf.sh` (les deux images) :** chaque page fait exactement 4 KiB, est alignée et ne contient **que** les symboles listés (liste exacte, sans préfixe), plus ses bornes à l'adresse de début ; chaque objet attendu est présent.
- **Suite « K0.7 critical layout (P4b) » (10 vérifications) :**
  - géométrie (alignement, taille, contiguïté, tête de `.bss`) ;
  - `sgdt` = `gdt_table()` dans `kcpu` ; `sidt` = `idt_table()` dans `kro_idt` ; `str` = TSS principal ; les deux TSS dans `kcpu` ;
  - `g_irq_depth`, `g_pmm`, `g_meta`, le TSS et la GDT hors des pages candidates à la lecture seule ;
  - **les quatre pages présentes et inscriptibles**, sans U ; CR0.WP actif ;
  - CR3 = `__kernel_end`.
- **Mutations `mutant_tool`, compilation réussie, donc détection fonctionnelle :**
  - `p4b_rw_in_vmm_page` : `g_tables` placé dans `kro_vmm`, détecté (« intrus:g_tables ») ;
  - `p4b_rw_in_handlers_page` : `g_exc_depth` placé dans `kro_handlers`, détecté (« intrus:g_exc_depth »).

### 11.6 Structures qui ne pourront pas être scellées

| Structure | Raison |
|---|---|
| GDT, TSS principal, TSS #DF | le CPU y écrit lors de la commutation de tâche de la #DF (triple fault mesuré en P4a). Isolées dans `kcpu`, elles ne partagent plus leur page avec l'IDT, les gestionnaires ou les compteurs |
| `g_exc_depth`, `g_irq_depth`, `g_in_panic` | écrits à chaque interruption ou panique |
| `g_tables` | incrémenté à chaque nouvelle table |
| `g_pmm`, `g_meta` | écrits à chaque allocation, libération, référence |
| tables de pages et répertoire | **pas encore** : demandent la fonction de passage de P4c, puis P4e |

`g_bootinfo` et `g_memmap` (initialisation seulement) n'ont pas été déplacées. Elles pourront l'être avec P4d, si le développeur le souhaite.

### 11.7 Risques résiduels après P4b

- **Aucune protection nouvelle :** P4b ne fait que préparer. Toutes les structures restent inscriptibles par l'identité ; P4 reste entièrement ouvert.
- La page `kcpu` (GDT, TSS) restera inscriptible après P4d.
- Le contrôle porte sur les **symboles** : un objet sans symbole ajouté dans une section `.bss.p4_*` serait détecté par les assertions de taille seulement s'il dépasse la page.
