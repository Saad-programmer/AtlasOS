# K0.7-P4d — Scellement des structures critiques immuables

**Statut :** mis en œuvre. Les pages `kro_idt`, `kro_handlers` et `kro_vmm` (P4b) sont **en lecture seule** après l'initialisation.
**Décision du développeur :** **aucune fenêtre CR0.WP en production.** Le scellement passe par les tables de pages, encore inscriptibles en P4d. CR0.WP reste actif en permanence, et le prototype P4c reste limité à l'image de test.
**Base :** commit `f1ae383` ; `main` inchangé ; aucune PR ouverte.

## 1. Audit préalable des écritures

**Références recensées :** toutes les références aux objets des trois pages, directes et par pointeur.
- **Aucune adresse n'échappe en écriture.** `idt_table()` renvoie un pointeur `const`, et seul l'IDTR contient l'adresse de l'IDT, lue par le CPU.
- `g_pd[...] = …` (dans `get_table`) écrit dans le **répertoire** désigné par `g_pd`, et non dans la variable `g_pd`.

| Page | Écritures logicielles (production) | Dernière écriture au démarrage | Écritures du CPU | Données mutables dans la page |
|---|---|---|---|---|
| `kro_idt` (`g_idt`) | `idt_init` (`memset`, `idt_set`) ; `idt_set_present` depuis `irq_register` | `irq_register(1)` dans `keyboard_init` | **aucune** (les portes n'ont pas de bit « accédé ») | aucune (`check_elf.sh`, P4b) |
| `kro_handlers` (`g_handlers`, `g_irq_handlers`) | `interrupt_register` (#PF, dans `paging_init`) ; `irq_register` (PIT, clavier) | `keyboard_init` | aucune | aucune |
| `kro_vmm` (`g_idmap_top`, `g_pd`) | `paging_init` seulement (une fois) | `paging_init` | aucune | aucune (`g_tables` est resté dans `.bss`) |

**Écritures hors production (image de test) :**
- `interrupt_register` et `interrupt_unregister` dans `test_cpu` (suites) ;
- `idt_set_present` dans les modes `df` et `dfsentinel` ;
- `interrupt_register` dans le mode `nested`.

**Aucune page ne doit être modifiée normalement après l'initialisation en production.**

## 2. Mécanisme

- **`paging_seal_identity(start, end)`** (`paging.c`) : opération **à sens unique**. Elle retire `PTE_WRITE`, puis exécute `INVLPG`.
  - **Toutes** les préconditions sont vérifiées avant la première modification : pagination active ; bornes alignées ; `start < end <= g_idmap_top` (sinon `EINVAL`) ; chaque page présente, en identité, de type `FRAME_KERNEL` (sinon `EPERM`).
  - Il n'y a donc pas de scellement partiel en cas de refus.
  - Les identités ne sont pas comptées : **aucune référence PMM ne change**.
- **`paging_seal_critical()`** : trois appels, un par page, sur des lignes distinctes pour les mutations. La fonction est idempotente.
- `paging_classify` reconnaît la faute : « write to a sealed kernel structure (IDT, handler tables or VMM roots) ».

## 3. Moment du scellement

**Production** (`kmain`) :

```text
idt_init -> mm_init (paging_init : interrupt_register #PF) -> pic_init
-> pit_init (irq_register 0) -> keyboard_init (irq_register 1)
-> [image de test seulement : ktest_run_all si « test »]
-> paging_seal_critical()            <- APRÈS la dernière écriture légitime
-> "SAMOS: critical structures sealed read-only (...)" -> idle_loop
```

En cas d'échec, `panic`.

**Image de test** (`ktest_run_all`) :
- **suites** : toutes les suites existantes (dont `test_cpu`, qui enregistre et retire des gestionnaires), **puis** le scellement de production, **puis** la suite « K0.7 sealed structures (P4d) ». Aucune page n'est laissée inscriptible en permanence ;
- **modes destructifs** : scellement **avant** le mode, sauf `df`, `dfsentinel` et `nested`, qui écrivent volontairement dans l'IDT ou les gestionnaires pour provoquer leur faute. La double faute en état **scellé** est démontrée par `stack` (débordement de S1, sans écriture de l'IDT).

## 5. Preuves

### 5.1 Positives (suite « K0.7 sealed structures (P4d) », 31 vérifications, après scellement)

- **Droits :** `idt_ro`, `handlers_ro` et `vmm_ro` : présentes, identité, sans W ni U ; CR0.WP actif.
- **Écriture refusée** par le MMU sur le premier mot de chaque page (et le dernier de `kro_vmm`) : CR2 exact, **code 3** (présente, écriture, superviseur), contenu inchangé.
- **Aucun alias :** parcours de **toutes** les PTE présentes. Chaque cadre scellé a **exactement une** projection, l'identité, sans W. `vmm_map` d'un alias de l'IDT ou de `kro_vmm` est refusé (`EPERM`).
- **Le noyau scellé fonctionne :** `sidt` = `kro_idt` ; **IRQ0 livrées** (au moins 3 tics du PIT, interruptions activées) ; #PF traitée (sonde) ; `vmm_map` et `vmm_unmap` d'un cadre alloué, avec des références exactes.
- **`paging_seal_identity` :** refus sans effet (hors identité `EINVAL`, non alignée `EINVAL`, cadre `ALLOCATED` `EPERM` et la page reste inscriptible, page nulle `EPERM`) ; deuxième appel de `paging_seal_critical` : `OK`.
- **Ce qui reste RW :** `kcpu`, PMM (`g_pmm`, `g_meta`), répertoire, première table. Les trois gardes restent absentes ; `pmm_core_check` à 0.

**Cas QEMU exécutés en état scellé** (motif « [TEST] critical structures sealed ») :
- `exc_ud` (exception) ;
- `stack_overflow` (double faute sur S2) ;
- `canary_smash` ;
- `keyboard_e2e` (IRQ1, frappes réelles) ;
- ainsi que tous les autres modes, sauf `df`, `dfsentinel` et `nested`.

### 5.2 Négatives (cas QEMU isolés)

`sealidt`, `sealhandlers` et `sealvmm` écrivent **directement** (pas par une sonde) dans la première adresse de chaque page scellée :
- « CPU exception 14: Page Fault (#PF), error code 0x00000003 », « protection violation, write access, supervisor mode » ;
- diagnostic « write to a sealed kernel structure (...) », statut **37** ;
- ni triple fault, ni double faute, ni panique récursive ;
- CR2 = `__kro_*_start` lu par `nm` (`0x11b000`, `0x11c000`, `0x11d000`).

### 5.3 Mutations

| Mutation | Effet | Détection |
|---|---|---|
| `seal_idt_removed` | l'IDT n'est plus scellée | `idt_ro`, `write_refused(__kro_idt_start)` (4 échecs) |
| `seal_handlers_removed` | les gestionnaires ne sont plus scellés | `handlers_ro`, `write_refused(__kro_handlers_start)` (3 échecs) |
| `seal_vmm_removed` | les racines du VMM ne sont plus scellées | `vmm_ro`, `write_refused(__kro_vmm_start)` (4 échecs) |

Si la sonde réussit sous mutation, elle **restaure** aussitôt la valeur : l'échec reste une assertion, et ne devient pas une corruption de l'IDT ou des racines du VMM, qui rendrait la mutation INVALIDE.

## 6. Production

- `check_elf.sh --production` : **une seule** écriture de CR0, dans `paging_init` (pose de PG et WP), et aucun symbole de test. Le prototype `test_ptgate.c` et `test_sealed.c` sont absents de l'image : 0 symbole `ptgate*`, `ktest_suite_sealed` ou `ktest_sealed_write`.
- Les tables de pages et le répertoire restent RW, de même que la GDT, les TSS et le PMM ; les trois gardes restent absentes ; les droits de `.text` et `.rodata` sont inchangés.

## 7. Effets sur les autotests

- Les suites qui enregistrent des gestionnaires (`test_cpu`) s'exécutent **avant** le scellement ; elles retirent leurs gestionnaires. L'état scellé est ensuite vérifié par une suite dédiée.
- Les modes `df`, `dfsentinel` et `nested` s'exécutent **sans** scellement, car ils écrivent volontairement dans l'IDT ou les gestionnaires. C'est le seul cas où une page candidate reste inscriptible, limité à l'image de test et à ces trois modes.
- **Après le scellement**, aucune fonction de test n'écrit dans les pages scellées, hors des sondes (qui fautent) et des trois modes destructifs.

## 8. Limitations et risques résiduels

- **P4 n'est réduit que pour trois pages.** Le répertoire et les tables de pages restent inscriptibles par l'identité. Une écriture parasite peut donc **remettre W** dans la PTE d'une page scellée, ce qui annule le scellement. C'est l'objet de P4e.
- La GDT, les TSS (écrits par le CPU), le PMM et les compteurs restent inscriptibles.
- **Plus d'enregistrement de gestionnaire après l'initialisation :** `interrupt_register` et `irq_register` provoqueraient une #PF, donc une panique. C'est un comportement **voulu** (échec sûr), mais une contrainte pour les futurs pilotes : ils devront s'enregistrer avant le scellement, ou attendre un passage d'écriture contrôlé en production, ce qui demandera une décision du développeur.
- `g_bootinfo` et `g_memmap` (initialisation seulement) ne sont pas scellées.
- P5 : du code ring 0 peut toujours écrire CR0.

## 9. Dépendances de P4e

1. Les tables de pages et le répertoire ne peuvent être protégés **qu'avec** un chemin d'écriture contrôlé pour `map_page`, `vmm_unmap` et `get_table` ; aujourd'hui, seul le prototype P4c (CR0.WP) existe, et il est interdit en production.
2. **Décision requise du développeur :** autoriser une fenêtre CR0.WP en production (P4c, avec la règle de `check_elf.sh` révisée), ou choisir une autre méthode (P4c §2 : B et C laissent un alias résiduel).
3. Ordre imposé : la première table, qui porte les PTE de toutes les tables, doit être scellée en **dernier** (P4a).
4. Les tables créées après le démarrage doivent être passées en lecture seule avant d'être reliées au répertoire.
5. Une fois P4e fait, le scellement de P4d deviendra effectivement **irréversible** pour une écriture parasite, puisque sa PTE ne sera plus modifiable par l'identité.
