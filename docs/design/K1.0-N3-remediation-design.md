# K1.0 — Correction de N3 : cohérence entre références physiques et projections virtuelles (conception)

**Nature :** document de conception. **Aucun code de production n'est modifié.** L'implémentation attend l'autorisation du développeur.
**Branche :** `claude/k1.0-n3-design`, depuis `main` = `a7a6e2c` (P4 intégré).
**Statut du projet :** K0.7 **non clôturé** ; K1.0 est un jalon préparatoire **isolé** : pas de migration x86-64, pas de nouvel espace d'adressage, pas de `kmalloc`.
**Sources relues :** `kernel/mm/pmm.c`, `kernel/mm/pmm_core.c`, `kernel/arch/i386/paging.c` (`map_page`, `vmm_unmap`, `table_create`, `pt_gate_check`, `frame_has_foreign_alias`), `docs/review/K0.7-P4f-E-closure-readiness.md` §4, `docs/review/K0.7-P4-closure.md` §7.

---

## 1. Rappel du défaut

N3 (P4f-E §4) : le PMM décide de **libérer** un cadre d'après le champ `refs` de son descripteur (`g_meta`), et de le **distribuer** d'après son type (`FRAME_FREE`). Ces deux champs sont des **données inscriptibles** du noyau. Rien ne vérifie, au moment de libérer ou de distribuer, qu'aucune projection dynamique ne désigne encore le cadre.

## 2. Reproduction (copie jetable, 2026-11-19)

**Montage :** une copie de `a7a6e2c` dans le répertoire temporaire de la session, avec un mode isolé ajouté (`test=n3repro`) qui n'est **jamais versionné**. Image de test, QEMU TCG, 128 MiB. Les falsifications écrivent directement dans `g_meta` et `g_pmm`, comme le ferait une écriture parasite du noyau.

| Cas | Opérations | Observé (journal debugcon) |
|---|---|---|
| **R1** : falsification de `refs` | `x = pmm_alloc_frame()` ; `vmm_map(0xD0001000, x, W)` ; libération légitime ; `refs` 1 → 0 (écriture de 16 bits) ; libération | descripteur `0x0013`, `refs = 1` ; libération légitime **−9 (EBUSY)** ; après falsification `desc = 0x0003`, `pmm_core_check = 0`, audit **propre** ; libération **0 (OK)** et `desc = 0x0000` (FREE) |
| R1 : réattribution | allocations et libérations **légitimes** en glissement, **sans forcer** `hint` | **même cadre** rendu au bout de **32 267** opérations (le next-fit a fait le tour), remis à zéro |
| R1 : accès par l'ancienne projection | le nouveau propriétaire écrit `0x5EC12E70` par l'identité ; l'ancienne VA lit, puis écrit `0x0BADC0DE` | l'ancienne VA **lit `0x5ec12e70`** ; le nouveau propriétaire **voit `0x0badc0de`**. Fuite **et** corruption croisée ; audit propre, `pmm_core_check = 0` |
| **R3** (nouveau) : consommation de la référence d'autrui | le nouveau propriétaire projette aussi le cadre (`0xD0003000`, `refs = 1`) ; l'**ancien** propriétaire retire sa projection | `vmm_unmap(0xD0001000)` = **0** ; `refs` passe à **0** alors que `0xD0003000` est **toujours projetée** ; le nouveau propriétaire libère alors le cadre : **0 (OK)**. **Une seule falsification, puis uniquement des opérations légitimes**, recrée N3 à la génération suivante |
| R1b : échec de `vmm_unmap` | cadre falsifié, libéré, réattribué ; l'ancien propriétaire tente de retirer sa projection | `vmm_unmap` = **−1 (EINVAL)** : le cadre est ALLOCATED avec `refs = 0`, la fonction refuse « sans rien toucher ». **La projection périmée reste en place** et ne peut pas être retirée |
| **R2** : falsification du type | cadre projeté, descripteur := FREE, `free_count + 1`, sans `pmm_free_frame` | `pmm_core_check = 0`, audit propre ; **même cadre** distribué ; l'ancienne VA lit `0x00000000` (remise à zéro), puis le secret `0x5ec12e72` du nouveau propriétaire ; `vmm_unmap` = −1, projection conservée |
| **R4** : type → KERNEL sur un cadre projeté | `vmm_unmap` | **0** : la PTE est effacée, **sans** `pmm_unref` (la fonction se croit dans le cas « non compté ») ; la référence est **perdue** (`desc = 0x0002`) ; audit propre |
| **R5** : type → PAGETABLE sur un cadre projeté | audit, puis `vmm_unmap` | audit **en échec** (`unpublished ≥ 1`, le seul cas vu) ; `vmm_unmap` = 0 sans `pmm_unref` |
| **R6** (nouveau) : cadre projeté distribué **comme table** | type := FREE, `hint` := ce cadre, puis `vmm_map` dans une région sans table (`0xE0000000`) | panique D1 : `page-table creation: frame already mapped elsewhere`. Mais au point d'arrêt (GDB sur `table_create_fatal`), le cadre lit `0x00000000…` : **les données de l'ancien propriétaire (`0xDA7A0000…`) ont été effacées avant la détection**. D1 s'arrête bien, mais **après** la remise à zéro de `alloc_zeroed` |

**Conclusions :**
- N3 est reproduit dans ses **deux variantes** : `refs` (R1) et type (R2).
- La réattribution se produit **sans** falsification de `hint` : le next-fit y revient naturellement.
- `vmm_unmap` **échoue** (R1b, R2) ou **décide à tort** (R3, R4, R5), parce qu'il déduit « projection comptée » du **type PMM**.
- Ni `pmm_core_check` ni `paging_audit` ne voient R1, R2, R3 ou R4.

## 3. Invariants manquants

On distingue deux sortes de projections :
- **Identité permanente :** `va < g_idmap_top`, cadre = `va`, imposée par le passage contrôlé, créée avant l'activation de la pagination et **jamais comptée**. Elle projette **toute** la RAM gérée ; ce n'est pas un alias à refuser.
- **Projection dynamique :** `va ≥ g_idmap_top`, créée uniquement par `map_page(counted = true)` : une PTE, une référence.

| Invariant | Énoncé | Garanti aujourd'hui par | Violé par |
|---|---|---|---|
| **N3-I1** (libération) | un cadre n'est jamais rendu FREE tant qu'une PTE présente à `va ≥ g_idmap_top` le désigne | `refs` seul (falsifiable) | R1, R3 |
| **N3-I2** (distribution) | un cadre n'est jamais distribué, **ni remis à zéro**, tant qu'une telle PTE existe | le type FREE seul (falsifiable) ; D1 seulement pour les tables, et **après** la remise à zéro | R1, R2, R6 |
| **N3-I3** (comptabilité du retrait) | toute PTE présente à `va ≥ g_idmap_top` est une projection **comptée**, quel que soit le type PMM courant | rien : `vmm_unmap` relit le type PMM | R3, R4, R5 |
| **N3-I4** (retrait toujours possible) | le retrait d'une projection dynamique ne peut pas être bloqué par une incohérence de métadonnées (retirer ne donne jamais d'accès) | rien : EINVAL laisse la projection | R1b, R2 |
| **N3-I5** (détection) | une incohérence entre `refs` et le nombre réel de projections dynamiques est visible à l'audit | rien | R1, R3, R4 |

**Garantie visée (K1.0) :** même si `refs`, le type, `free_count` ou `hint` sont falsifiés, aucun cadre encore projeté dynamiquement n'est libéré, distribué ni remis à zéro. Un refus doit soit être **sans effet** (erreur ordinaire, métadonnées inchangées), soit être un **arrêt déterministe avant toute écriture** dans le cadre. **Les compteurs PMM ne sont pas une source de vérité.**

## 4. Approches étudiées

### 4.1 Approche A : vérification des projections avant libération et réattribution

**Principe :** la source de vérité est l'ensemble des **tables de pages publiées**. Elles sont scellées en lecture seule (P4e-2) et n'ont qu'un seul écrivain, le passage contrôlé. Leurs PDE ne connaissent que la transition absente → présente (D3), donc l'ensemble des tables publiées ne fait que croître. Un oracle du VMM, `vmm_frame_dynamically_mapped(phys)`, parcourt les PTE à `va ≥ g_idmap_top`. C'est le critère déjà existant de D1 (`frame_has_foreign_alias`), sans le PMM.
- `pmm_free_frame` : si l'oracle répond vrai, il renvoie **EBUSY** sans aucune écriture dans `g_meta`.
- `alloc_zeroed` : si l'oracle répond vrai, **panique avant `memset`**, avec l'empreinte de la page. C'est le même modèle que N1 : le cadre a déjà été retiré de FREE par `pmm_core_alloc_as`, et le remettre FREE le ferait redistribuer aussitôt.

**Prototype (copie jetable, environ 15 lignes) :**

| Cas | Sans A | Avec A |
|---|---|---|
| R1 : libération falsifiée | 0 (OK) | **−9 (EBUSY)**, `desc = 0x0003` inchangé |
| R1 : réutilisation sur 70 001 allocations et libérations légitimes | cadre rendu au bout de 32 267 | **jamais rendu** ; l'ancienne VA ne voit que ses propres données (`0xa11ce000`) |
| R3 | `refs` d'autrui consommée, libération sous projection | **inatteignable** : le cadre n'est jamais réattribué ; libération sous projection : −9 |
| R2 | cadre projeté distribué et remis à zéro | **panique avant remise à zéro** : `frame … still mapped outside identity handed out as type 3; refused before zeroing` |
| R6 | données effacées, puis panique D1 | panique **dans le PMM, avant remise à zéro** ; GDB sur `panic_at` : le cadre lit encore `0xda7a0000 … 0xda7a03ff` (**intact**) |
| R1b (falsification de `refs` avec projection présente) | EINVAL, projection conservée | EINVAL, projection conservée : **plus aucune fuite croisée**, mais le cadre reste bloqué (fuite de disponibilité, même propriétaire) |
| R4, R5 | référence perdue au retrait | **inchangé** (A ne touche pas `vmm_unmap`) : fuite, pas de fuite croisée |

**Régressions du prototype :**
- `make test` : 176 `[PASS]`, 75 cas QEMU sur 77 ;
- les 2 échecs, `tablealias` et `tablealias_frame`, sont **attendus** : le même cadre (`0x001d8000`) est maintenant arrêté plus tôt, dans le PMM avant la remise à zéro, et non plus dans `table_create`. Le diagnostic attendu doit être recalé, comme pour M52 en P4f-D ;
- les vérifications GDB qui suivent dans `make test` n'ont pas été exécutées après cet échec ;
- les mutations n'ont pas été exécutées sur le prototype : **NOT TESTED**.

**Coût mesuré** (TCG, ×1024 cycles, 1 000 opérations, 2 exécutions de 3 mesures chacune) :

| Tables hors identité | `alloc` + `free`, sans A | avec A | facteur | `alloc` + `map` + `unmap` + `free`, sans A | avec A |
|---|---|---|---|---|---|
| 1 | 21,5-24,2 M | 68,6-75,4 M | ≈ ×3,2 | 53-69 M | 102-119 M (une valeur isolée à 281 M) |
| 8 | 21,2-22,9 M | 166-196 M | ≈ ×8 | 51-57 M | 191-368 M |
| 32 | 20,8-22,0 M | 462-628 M | ≈ ×22 | 51-58 M | 500-674 M |

Le coût est **linéaire en nombre de tables dynamiques** : environ 7 000 cycles TCG par table et par parcours, et il y a deux parcours par couple allocation-libération. Sans A, il ne dépend pas du nombre de tables. Sur matériel réel : **NON MESURÉ**.

### 4.2 Approche B : comptabilité des projections indépendante des descripteurs PMM

**Principe :** un compteur de projections par cadre, `mc[f]`, stocké dans des pages **scellées** et écrit seulement par le passage contrôlé, dans la même fenêtre que la PTE. Le PMM consulte `mc[f]` (lecture seule) avant de libérer ou de distribuer.
- **Robustesse aux deux variantes :** oui. `mc` n'est pas dans `g_meta` et n'est pas inscriptible hors du passage.
- **Complexité :** élevée.
  - Elle rompt l'invariant **« une seule écriture de 32 bits par fenêtre WP »** de P4e-1, vérifié par `check_elf.sh`, puisqu'il faut écrire la PTE et le compteur. Il faut donc refondre le passage et ses contrôles du code machine, ou ouvrir deux fenêtres par opération.
  - Il faut une allocation au démarrage des pages de `mc`, leur scellement, et un audit de cohérence `mc` / PTE.
- **Mémoire :** 2 octets par cadre, soit 64 KiB pour 128 MiB et 512 KiB pour 1 GiB. Une variante « bit possiblement projeté » coûterait 32 KiB pour 1 GiB, mais son effacement exige un parcours : on retombe sur le coût de A au retrait.
- **CPU :** O(1) à la libération et à l'allocation ; une écriture de plus par `map` et `unmap`, dans la fenêtre ou dans une seconde fenêtre (sous QEMU, chaque basculement de CR0.WP vide tout le TLB).
- **Dépendances :** le PMM lit une structure du VMM, sans appel de fonction ; c'est une nouvelle **structure de confiance**.
- **Futurs espaces d'adressage :** naturel, puisque le compteur est global à tous les répertoires.
- **Compatibilité :** D1 à D4, N1, N2 et N5 sont conservés. C'est le **passage** (P4e-1) qui change : c'est un changement d'architecture.

### 4.3 Approche C : interface de gestion des cadres contrôlée par le VMM

**Principe :** les cadres projetables ne se libèrent que par `vmm_release(va)`, qui retire la projection puis libère ; `pmm_free_frame` refuse ces cadres.
- **Robustesse :** **aucune** face à la falsification. Pour savoir qu'un cadre est « projetable », il faut un type ou un drapeau PMM, donc falsifiable : R2 contourne C directement. C supprime les **mauvais usages**, comme libérer sans retirer la projection.
- **Complexité :** moyenne (règle de propriété, refonte des appelants ; aujourd'hui, seuls les autotests sont concernés).
- **Coûts :** négligeables.
- **Dépendances :** saines, VMM → PMM uniquement.
- **Futurs espaces d'adressage :** utile pour la propriété (qui a le droit de libérer), indispensable à terme avec des processus ; ne règle pas N3.
- **Compatibilité :** totale ; ne remplace aucune protection.

| Critère | A | B | C |
|---|---|---|---|

## 5. Recommandation

### 5.1 Solution retenue pour K1.0 : A, complétée par le durcissement du retrait (N3-I3, N3-I4) et un audit (N3-I5)

**Pourquoi A :**
- c'est la **seule** approche qui corrige les deux variantes **sans** nouvelle structure de confiance ni modification du passage ;
- elle étend un critère **déjà prouvé** (D1, P4f-B1) et ne s'appuie que sur des invariants établis : tables scellées (P4e-2), PDE à écriture unique (D3), identité exacte (frame = va) imposée par le passage ;
- son coût est **nul en production aujourd'hui**, puisque aucun code de production n'appelle `vmm_map`, et il n'y a donc aucune table dynamique ;
- il reste acceptable tant que les tables dynamiques sont peu nombreuses, ce qui est le cas de K1.0 à K1.2.

**Pourquoi pas B maintenant :** B modifie le passage, c'est-à-dire l'invariant central de P4, et ajoute une structure de confiance. C'est une **décision d'architecture**, à prendre en K1.4 (plusieurs espaces d'adressage) **et** si les mesures de A deviennent prohibitives. C reste une amélioration de **propriété** à introduire avec les processus, sans la présenter comme une correction de N3.

### 5.2 Couplage PMM → VMM

`pmm.c` dépend déjà de `arch/paging.h` (`PAGING_IDMAP_LIMIT`). Il y a trois possibilités pour l'oracle :

| Option | Évaluation |
|---|---|
| **appel direct** à `vmm_frame_dynamically_mapped()`, déclaré dans `arch/paging.h` | **recommandé** : lien statique, sans état ; l'oracle renvoie faux avant la pagination (aucune projection dynamique n'existe) et si `g_pd == 0` |
| pointeur de fonction enregistré par le VMM | **refusé** : un pointeur de fonction en données inscriptibles est une **cible de détournement** ; il faudrait le sceller |
| enveloppes dans le VMM uniquement (`vmm_free_frame`) | insuffisant : un appel direct à `pmm_free_frame` contourne la vérification (c'est la faiblesse de C) |

Il n'y a pas de cycle : l'oracle **n'appelle pas** le PMM ; il lit seulement `g_pd` (scellé) et les tables publiées, par l'identité.

### 5.3 Retrait (`vmm_unmap`) : décision du développeur requise

Avec A, R3 devient inatteignable, mais R1b, R4 et R5 subsistent. Leur effet est seulement une fuite ou un blocage chez le même propriétaire.

| Option | Comportement | Effet |
|---|---|---|
| **U1** : conserver le contrat M2.4d | EINVAL, projection intacte | le cadre reste projeté et non libérable (fuite de disponibilité) ; aucune fuite croisée grâce à A |
| **U2** : retrait sûr, **recommandé** | toute PTE à `va ≥ g_idmap_top` est **comptée** (N3-I3) ; le retrait efface toujours la PTE et exécute INVLPG ; `pmm_unref` seulement si le type est ALLOCATED et `refs > 0` ; sinon compteur d'anomalie `unmap_ref_anomalies`, sans écriture dans `g_meta` | retirer ne donne jamais d'accès (N3-I4) ; après retrait, A autorise la libération ; l'ordre passage < INVLPG < `pmm_unref` (D2, `check_elf.sh`) est conservé |

U2 change un contrat documenté (M2.4d : « en cas de refus, la projection reste intacte »). C'est pourquoi il faut ta décision.

### 5.4 Distinction identité et projections dynamiques

- L'oracle ne parcourt que `va ≥ g_idmap_top` : l'identité n'est **jamais** comptée, conformément à N3-I3.
- Le passage interdit toute PTE d'identité où `frame ≠ va` : un cadre ne peut donc apparaître sous `g_idmap_top` qu'à sa propre adresse.
- Il n'y a pas de grandes pages : la PDE doit valoir exactement `P | W`.

### 5.5 Refus sans corruption silencieuse

| Chemin | Refus | Preuve demandée |
|---|---|---|
| `pmm_free_frame` | EBUSY, **aucune** écriture dans `g_meta`, `free_count` ni `hint` ; compteur dédié `mapped_frees`, distinct de `busy_frees` (un refus par l'oracle alors que `refs = 0` prouve une incohérence) | descripteur, `free_count` et `hint` identiques avant et après |
| `alloc_zeroed` | panique **avant** `memset`, avec l'empreinte FNV de la page | empreinte au refus égale à l'empreinte avant (banc QEMU, comme pour N1), et vérification GDB |
| `table_create` (D1) | devient une **seconde couche** | une mutation qui retire la première couche doit faire réapparaître le diagnostic D1 |

## 8. Limites de la solution (à conserver dans le registre)

- **Un seul espace d'adressage.** En K1.4, l'oracle doit parcourir **tous** les répertoires, ce qui suppose un registre des répertoires lui-même scellé. Son coût croît avec la somme des tables : il faut alors réexaminer B.
- **Confiance dans les tables.** La garantie suppose l'intégrité des structures scellées (P4e-2), du passage et de `g_pd`. Une écriture capable de contourner CR0.WP, comme du code en ring 0 malveillant, n'est pas couverte.
- **Identité inscriptible.** Tout code ring 0 peut encore écrire **n'importe quel cadre** par l'identité. La correction empêche la **redistribution** d'un cadre projeté, pas l'écriture arbitraire du noyau. L'isolation réelle exige des espaces d'adressage séparés (K1.4).
- **Disponibilité.** Un `refs` falsifié **vers le haut**, ou un type falsifié en KERNEL ou RESERVED, rend un cadre définitivement non libérable : c'est une fuite, détectée par l'audit seulement. R2 et R6 se terminent par un **arrêt** : la sûreté est préservée, pas la disponibilité.
- **Propriété.** `vmm_map` peut toujours projeter **n'importe quel** cadre ALLOCATED, il n'existe pas de notion de propriétaire. C'est hors du périmètre de N3, à traiter avec C et les processus.
- **Monoprocesseur, sans projection dans les interruptions.** Entre le contrôle et la libération, aucune concurrence n'est possible aujourd'hui (R-SMP).
- **Mesures sous TCG seulement** ; matériel réel non testé.

## 9. Ce que ce document ne fait pas

- Aucun code de production n'est modifié. Le prototype et le mode `n3repro` n'existent que dans une copie jetable, **non versionnée**.
- Aucune migration x86-64, aucun espace d'adressage, aucun `kmalloc`.
- K0.7 n'est pas clôturé. N3 reste **ouvert** jusqu'à une implémentation autorisée et validée.
