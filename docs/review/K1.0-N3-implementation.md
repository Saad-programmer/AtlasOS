# K1.0-N3-IMPLEMENT — Protection des cadres encore projetés

**Jalon :** K1.0, jalon préparatoire isolé. Ce n'est **pas** la migration x86-64. K0.7 n'est pas clôturé.
**Branche :** `claude/k1.0-n3-implement`, depuis `dbaf6d7` (conception). `main` = `a7a6e2c`, non modifié.
**Décisions du développeur :** approche **A** (vérification indépendante des projections) ; **U2 sous condition de sûreté** pour `vmm_unmap`.
**Statut :** implémenté et vérifié sous QEMU ; **en attente de validation**. K1.0 n'est pas déclaré terminé.
**Périmètre des garanties :** monoprocesseur, espace d'adressage **unique**, i386, QEMU TCG.

---

## 1. Cause racine

Avant K1.0, trois décisions reposaient sur des champs **inscriptibles** du descripteur PMM (`g_meta`) :

| Décision | Fondée sur | Conséquence d'une falsification |
|---|---|---|
| libérer un cadre (`pmm_core_free`) | `refs == 0` | un cadre encore projeté redevient FREE (R1) |
| distribuer un cadre (`pmm_core_alloc_as`, puis `alloc_zeroed`) | type FREE | un cadre projeté est remis à zéro et donné à un autre propriétaire (R1, R2) ; comme table, il est effacé **avant** l'arrêt D1 (R6) |
| rendre une référence au retrait (`vmm_unmap`) | type ALLOCATED, `refs > 0` | retrait impossible (R1b, R2), référence perdue (R4, R5) ou référence d'**un autre** propriétaire consommée (R3) |

Aucune de ces décisions ne consultait la réalité, c'est-à-dire les PTE présentes. Or les tables de pages, elles, sont protégées depuis P4 : scellées en lecture seule (P4e-2), un seul écrivain (le passage contrôlé), PDE à écriture unique (D3).

## 2. Architecture retenue

### 2.1 Oracle des projections (N3-I3)

`kernel/arch/i386/paging.c` contient :
- `dyn_mapping_count(frame, limit)` : compte les PTE présentes à `va ≥ g_idmap_top` qui désignent `frame`, dans les tables du répertoire actif ;
- `vmm_frame_dynamically_mapped()` et `vmm_dynamic_mappings()` : son interface publique, dans `arch/paging.h`.

| Propriété | Réalisation |
|---|---|
| Indépendance du PMM | ne lit ni le type ni `refs` ; seulement `g_pd` (page scellée en P4d) et les tables publiées (scellées) |
| Identité exclue | test `va ≥ g_idmap_top` **PTE par PTE**. La table de la frontière (PDE de `g_idmap_top`, quand celui-ci n'est pas multiple de 4 MiB, par exemple `0x07fe0000` à 128 MiB) contient à la fois l'identité et des projections dynamiques |
| Grandes pages | impossibles : le passage n'accepte que des PDE égales à `P \| W` |
| Avant `paging_init` | `g_pd == 0`, donc 0 projection |
| Appel | **direct** depuis `pmm.c` (pas de pointeur de fonction inscriptible) |
| Cycles et récursion | aucun : lecture seule, sans allocation ni appel au PMM |
| Réentrance | aucun gestionnaire d'interruption n'alloue, ne libère ni ne projette (monoprocesseur) ; l'oracle ne masque pas les interruptions (il ne modifie rien) |
| D1 | `frame_has_foreign_alias` (P4f-B1) est désormais `dyn_mapping_count(frame, 1) != 0` : même critère, une seule implémentation |

**Phases d'initialisation.** `paging_init` fixe `g_idmap_top` avant d'allouer le répertoire. Pendant la construction de l'identité, les allocations de tables appellent l'oracle :
- avant l'affectation de `g_pd`, il renvoie 0 ;
- ensuite, il ne parcourt que les PDE à partir de celle de `g_idmap_top`, et dans la table de la frontière seulement les PTE à `va ≥ g_idmap_top`. Il n'en existe aucune à ce stade, donc la réponse est correcte ;
- les tables sont lues à leur adresse physique, égale à l'adresse virtuelle, avant comme après PG.

### 2.2 Libération (N3-I1) : `pmm_free_frame`

Si l'oracle répond vrai, la libération renvoie **EBUSY**, **avant** toute lecture du descripteur et sans aucune écriture (`g_meta`, `free_count`, `hint`). Le compteur dédié `mapped_frees` est distinct de `busy_frees` (refus par `refs`). Le contrôle `refs` de `pmm_core_free` reste la **seconde barrière** : il protège les références prises sans projection.

### 2.3 Distribution et remise à zéro (N3-I2) : `alloc_zeroed`

Après le contrôle N1 et **avant `memset`**, si l'oracle répond vrai, le noyau panique avec l'adresse, le nombre de projections, le type demandé et l'empreinte FNV-1a de la page. Ce contrôle couvre les **deux** chemins de distribution, `pmm_alloc_frame` (données) et `pmm_alloc_pagetable` (tables), ce sont les seuls appelants de `pmm_core_alloc_as`.

Le refus est un arrêt plutôt qu'une erreur parce que `pmm_core_alloc_as` a déjà retiré le cadre de FREE. Le remettre FREE le ferait redistribuer aussitôt : c'est le même modèle que N1.

Le contrôle D1 de `table_create` devient une **seconde couche**, éprouvée par le mode `tablealias_l2`. Ce mode neutralise la première couche par `pmm_test_skip_n3_alloc_check()`, qui n'existe que dans l'image de test (dans l'image de production, la macro vaut `true`).

### 2.4 Retrait (N3-I4) : `vmm_unmap`, U2 sous condition de sûreté

| Situation | Comportement | Écriture dans `g_meta` |
|---|---|---|
| cohérente : ALLOCATED, `refs = D` | PTE effacée, INVLPG, `pmm_unref` | `refs - 1` |
| excès : ALLOCATED, `refs > D` (référence prise pour une autre raison, ou falsifiée vers le haut) | PTE effacée, INVLPG, `pmm_unref` | `refs - 1 ≥ D - 1` : chaque projection restante garde sa référence |
| déficit : ALLOCATED, `refs < D` (y compris `refs = 0`, R1b) | PTE effacée, INVLPG, **pas** de `pmm_unref`, `vmm_unmap_ref_anomalies` + 1 | **aucune** |
| type falsifié (FREE, KERNEL, PAGETABLE, RESERVED : R2, R4, R5) | PTE effacée, INVLPG, anomalie comptée | **aucune** |
| plusieurs projections, l'une retirée | `D` compte toutes les projections, celle-ci comprise : la règle ci-dessus s'applique | — |

Ici, `D` est le nombre **réel** de projections dynamiques du cadre, relevé **avant** l'effacement (`D ≥ 1`).

- **Règle :** `pmm_unref` si et seulement si le type est ALLOCATED et `refs ≥ D`.
- **Propriété :** après le retrait, `refs' ≥ min(refs, D - 1)`. Un déficit ne s'aggrave jamais et **aucune projection restante ne perd sa référence**.
- **Pourquoi pas de réparation :** réparer (`refs := D - 1`, type := ALLOCATED) supposerait de connaître le vrai type et les références prises pour d'autres raisons, ce que rien de fiable n'indique. On a donc choisi le **refus fermé** sur les métadonnées et le **retrait toujours effectif** de la PTE (retirer ne donne jamais d'accès).
- **Sûreté de la libération :** elle ne dépend plus de `refs`. Après le dernier retrait, l'oracle autorise la libération si `refs = 0`. Un excès bloque la libération : c'est une fuite de disponibilité, signalée par l'audit (`ref_surplus`).
- **D2 :** l'ordre passage < INVLPG < `pmm_unref` est conservé, et `check_elf.sh` le vérifie toujours (règle `vmm_unmap pmm_unref`).

**Limite (hors N3, refus fermé de P4) :** si le type PMM de la **table** ou du **répertoire** est falsifié, le passage refuse toute écriture dans cette table, retraits compris. La projection reste alors en place. Ce n'est pas une incohérence entre le cadre et ses projections, mais une protection de P4 (le passage refuse plutôt que d'écrire dans une structure douteuse). N3-I4 est satisfait pour toute incohérence portant sur le **cadre projeté**, et pas au-delà.

### 2.5 Audit (N3-I5) : `paging_audit`

| Compteur | Sémantique exacte | Fait échouer l'audit |
|---|---|---|
| `mapped_type_mismatch` | cadres **distincts** avec `D(f) ≥ 1` dont le type PMM n'est pas ALLOCATED (ou hors mémoire gérée) | oui |
| `ref_mismatch` | cadres ALLOCATED avec `refs < D(f)` : au moins une projection sans référence | oui |
| `ref_surplus` | cadres ALLOCATED avec `refs > D(f)` | **non** (informatif) |

- `D(f)` = projections dynamiques réelles, c'est-à-dire PTE à `va ≥ g_idmap_top`. L'identité n'est **jamais** comptée, d'où l'absence de faux positif sur les 128 MiB d'identité.
- Les cadres de l'image et les structures de pagination projetés hors identité sont **exclus** : ils sont déjà comptés par `foreign_aliases` (P4f-B1).
- **Références des projections et références prises pour d'autres raisons.** Un compteur unique ne permet pas de les distinguer. On ne signale comme défaut que la direction **dangereuse**, une projection sans référence (`ref_mismatch`). L'excès est **légitime** tant que `pmm_ref` reste une interface publique ; les autotests l'utilisent sans projection. Si un futur appelant de production utilise `refs` pour épingler des cadres, ces références devront être séparées.
- **Coût :** O(P × T) pour P projections dynamiques et T tables dynamiques, plus un relevé par cadre référencé. Acceptable au démarrage et dans les autotests (aucune projection dynamique en production).
- Le message de panique de l'audit au démarrage (`kmain.c`) inclut les deux nouveaux compteurs.

## 4. Expériences R1 à R6, avant et après

**Montage :** le même mode jetable `n3repro` (API de base seulement, jamais versionné) est compilé dans une copie de `a7a6e2c` (avant) et dans une copie de l'arbre K1.0 (après). QEMU TCG, 128 MiB. R2 est exécuté en dernier, puisqu'il est désormais fatal.

| Cas | Avant (`a7a6e2c`) | Après (K1.0) |
|---|---|---|
| R1 : libération après `refs` 1 → 0 | **0 (OK)** ; audit propre | **−9 (EBUSY)**, descripteur `0x0003` inchangé ; audit **en échec** (`ref_mismatch = 1`) |
| R1 : réutilisation naturelle | **même cadre** au bout de 32 266 opérations ; l'ancienne VA lit `0x5ec12e70` (secret du nouveau propriétaire), qui voit `0x0badc0de` | jamais réutilisé en 70 001 opérations ; l'ancienne VA lit **ses propres** données `0xa11ce000` |
| R3 : retrait par l'ancien propriétaire | `refs` du nouveau propriétaire : **1 → 0** ; libération sous projection : **0 (OK)** | `refs` du nouveau propriétaire reste **1** ; libération sous projection : **−9** |
| R1b : retrait d'une projection incohérente | **−1 (EINVAL)**, projection périmée **conservée** | **0**, projection **retirée** |
| R2 : type FREE falsifié | cadre projeté **réattribué**, l'ancienne VA lit `0x5ec12e72` ; retrait −1 | **panique avant remise à zéro** : `still mapped outside identity (1 dynamic mappings) handed out as type 3; refused before zeroing` |
| R4 : type KERNEL | retrait 0, référence perdue ; audit **propre** | retrait 0, `g_meta` intacte (anomalie comptée) ; audit **en échec** (`mapped_type_mismatch = 1`) |
| R5 : type PAGETABLE | retrait 0 ; audit en échec (`unpublished`) | retrait 0 ; audit en échec (`unpublished` **et** `mapped_type_mismatch`) |
| R6 : cadre projeté distribué comme table | arrêt D1 dans `table_create`. GDB (`table_create_fatal`) : le cadre lit `0x00000000 …`, données **effacées** | arrêt **dans le PMM** (`alloc_zeroed`). GDB (`panic_at`) : le cadre lit `0xda7a0000 0xda7a0001 0xda7a0002 0xda7a0003 … 0xda7a03ff`, **intact** (copie jetable, et mode `n3table` du dépôt) |

Le mode versionné `test=n3` rejoue R1, R1b, R2 (partie non fatale), R3, R4 et R5 avec des assertions nommées. Les modes `n3type` (R2) et `n3table` (R6) rejouent les cas fatals, et le banc QEMU exige une empreinte identique avant l'allocation et au refus (`0xc099f0c5`).

## 6. Coûts (TCG, ×1024 cycles, 1 000 opérations, minimum et maximum sur 6 mesures)

Mode de mesure jetable `n3bench`, compilé à l'identique dans les deux copies. Code source : §9.

| Tables dynamiques | `alloc` + `free`, base | K1.0 | facteur (min/min) | `alloc` + `map` + `unmap` + `free`, base | K1.0 | facteur |
|---|---|---|---|---|---|---|
| 0 | 23,6-28,0 M | 64,0-76,0 M | ×2,7 | — | — | — |
| 1 | 23,5-24,8 M | 68,1-129,4 M | ×2,9 | 58,0-61,2 M | 130,3-212,0 M | ×2,2 |
| 8 | 23,4-25,5 M | 157,7-210,5 M | ×6,7 | 55,9-61,1 M | 276,6-380,9 M | ×4,9 |
| 32 | 23,3-24,5 M | 528,9-644,7 M | ×22,7 | 57,3-59,6 M | 924,1-1041,9 M | ×16,1 |

**Lecture :**
- **Linéaire** en nombre de tables dynamiques : `alloc` et `free` parcourent chacun les tables (deux parcours par couple), et `vmm_unmap` en fait un troisième pour relever `D`.
- **Même sans table dynamique, environ ×2,7** à 128 MiB : la PDE de la frontière (31) porte la table d'identité de `0x07c00000` à `0x07fdffff`, dont les 1 024 PTE sont lues à chaque appel. Seules les 32 dernières, au-delà de `idmap_top`, peuvent être dynamiques.
- Une optimisation **équivalente** est identifiée : commencer le parcours de cette table à `PT_INDEX(g_idmap_top)`. Elle n'est **pas intégrée** : ce jalon n'en a pas l'autorisation, et la mutation `n3_identity_counted_in_boundary` devrait alors viser la borne de départ. De même, le préfiltre N4 n'est **pas intégré** (décision distincte).
- **Production :** aucune projection dynamique en K0, mais `pmm_alloc_frame` et `pmm_free_frame` paient le parcours de la table de la frontière quand `idmap_top` n'est pas multiple de 4 MiB.
- Matériel réel : **NON MESURÉ**.

## 8. Limites et risques résiduels

| Sujet | Description |
|---|---|
| Espace d'adressage unique | l'oracle ne lit que le répertoire actif. En K1.4 (plusieurs répertoires), il devra parcourir **tous** les répertoires, à partir d'un registre lui-même scellé, sans quoi N3 se rouvre. Réexaminer alors l'approche B (comptes scellés), compte tenu des coûts du §6 |
| Confiance dans les tables | la garantie suppose l'intégrité de `g_pd`, des tables scellées et du passage (P4). Du code ring 0 capable de contourner CR0.WP n'est pas couvert |
| Identité inscriptible | tout code ring 0 peut encore écrire n'importe quel cadre de données par l'identité. N3 empêche la **redistribution** d'un cadre projeté, pas l'écriture arbitraire du noyau |
| Disponibilité | un `refs` falsifié vers le haut, ou un type falsifié KERNEL ou RESERVED, rend un cadre définitivement non libérable : c'est une fuite, signalée par l'audit (`ref_surplus`, `mapped_type_mismatch` tant qu'il est projeté). R2 et R6 se terminent par un **arrêt** : la sûreté est préservée, pas la disponibilité |
| Retrait sous table falsifiée | cf. §2.4 : refus fermé du passage, projection non retirable |
| Propriété | `vmm_map` peut toujours projeter **n'importe quel** cadre ALLOCATED : il n'y a pas de notion de propriétaire (approche C, plus tard) |
| Références partagées | un seul compteur `refs` pour les projections et les autres usages. L'excès n'est pas une erreur ; à séparer si un épinglage de production apparaît |
| Concurrence | monoprocesseur, aucune projection ni allocation dans les gestionnaires d'interruption ; entre le contrôle et l'action, aucune concurrence n'est possible aujourd'hui (R-SMP) |
| Performance | coût linéaire en nombre de tables dynamiques (§6) ; TCG seulement |
| Matériel réel | non testé |

N3 est **corrigé dans le périmètre d'un seul espace d'adressage, monoprocesseur**, sous réserve de la validation du développeur. Ce n'est **pas** une garantie d'isolation mémoire.
