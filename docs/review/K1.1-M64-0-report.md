Conditions :
- répertoire temporaire hors dépôt ; image de production `build/samos.elf` de `63aca66` ;
- QEMU 8.2.2, GDB 15.1 ;
- options `-m 128M -display none -no-reboot -kernel samos.elf -gdb tcp::PORT -S`.

| Essai | `qemu-system-i386` | `qemu-system-x86_64` |
|---|---|---|
| `gdb samos.elf -ex 'target remote'`, architecture déduite (i386) | OK | **ÉCHEC** : `Remote 'g' packet reply is too long (expected 312 bytes, got 608 bytes)`, puis `Architecture rejected target-supplied description` |
| `set architecture i386` avant la connexion | OK | **ÉCHEC** (même message) |
| `set architecture i386:x86-64`, `target remote`, puis `symbol-file samos.elf` | **ÉCHEC** : `not compatible with reported target architecture i386` | OK |
| `break *kmain` → PC | `0x1029b0` = `&kmain` | `0x1029b0` = `&kmain` |
| ESP (`$esp`) | `0x196fec` | `0x196fec` (moitié basse de `$rsp`) |
| `$eip` | `0x1029b0` | **indisponible** (`Value can't be converted to integer`) ; `$pc` et `$rip` sont exacts |
| EFLAGS | `0x46` (DF=0, IF=0) | `0x46` (DF=0, IF=0) |
| CS, SS | `0x8`, `0x10` | `0x8`, `0x10` |
| `x/3wx $esp` (retour, magic, mbi) | `0x00100086 0x2badb002 0x00009500` | identique |
| Arguments C symboliques (`kmain (magic=…)`) | exacts | **FAUX** (`magic=0, mbi_phys=0`) |
| Désassemblage | exact | **FAUX** (code 32 bits décodé en 64 bits) |
| Commandes exactes de `gdb_checks.sh` (ABI, magic invalide, dump VGA) | ESPMOD16=12, ARG0=0x2badb002, ARG1=0x9500, DF=0, IF=0, INSTACK=1 ; panique « invalid multiboot magic 0xdeadbeef », arrêt, pas de « boot complete » ; texte VGA présent | **valeurs identiques** ; mêmes verdicts |
| GDB sans émulateur à l'écoute | `could not connect: Connection timed out.` ; un `printf` de **constante** s'exécute quand même en mode `-batch` : il faut lire des registres pour obtenir une preuve | même comportement |

Le contenu VGA diffère d'une ligne : l'écran x86_64 a défilé d'une ligne de plus, à cause d'une région E820 supplémentaire (§4). Les deux lignes cherchées par le banc sont présentes dans les deux cas.

**Conclusion.** Le port est fiable pour les vérifications **existantes**, à deux conditions :
- architecture `i386:x86-64` imposée avant la connexion ;
- uniquement des registres (`$esp`, `$eflags`), de la mémoire brute et des adresses de symboles.

Aucune vérification n'utilise `$eip`, le désassemblage ni les arguments symboliques. L'adaptation des bancs a donc été réalisée (§3). Ces limites sont documentées dans `tests/qemu/emu.sh` et dans `Details.md` §41.

Détail des nouveautés principales :
- **`emu.sh`, fonction `emu_probe` :**
  - identifie l'émulateur par QMP : modèle de CPU, chaîne CPUID, type de machine ;
  - refuse un émulateur absent, invalide ou d'une autre architecture (statut 2) ;
  - fournit l'architecture GDB.
- **`emu.sh`, fonction `emu_print` :** produit la ligne `[EMU]` de chaque rapport.
- **`gdb_checks.sh`, exigences par test :**
  - statut de GDB nul ;

  - valeurs attendues, inchangées ;
  - `vga.txt` vidé si le dump manque.
- **`emu_compare.sh`, éléments comparés :** verdicts (statut et nom), bilans `QEMU: N cas…` et `[TEST] skipped=N`. Un résultat absent est un échec (statut 2). Les écarts de mesure sont listés en `[INFO]`.

### Divergence relevée, puis traitée sans être masquée

La première exécution de la matrice a **échoué** :

```text
[FAIL] comparaison : DIVERGENCE entre build/emu/qemu-system-i386 et build/emu/qemu-system-x86_64
        < [PASS] n1low_page_intact (avant 0xd101c125, refus 0xfbe32763)
        > [PASS] n1low_page_intact (avant 0xcb942316, refus 0x9800a049)
        < [PASS] n1stack_page_intact (avant 0xd973ac1e, refus 0x770a88cb)
        > [PASS] n1stack_page_intact (avant 0x13975f42, refus 0x87a81bc6)
```

Analyse :
- **Verdicts :** ils sont identiques (`[PASS]`). La différence porte sur les **mesures** placées entre parenthèses.
- **n1stack :** l'empreinte de la pile active varie d'une exécution à l'autre **sous le même émulateur**. Trois exécutions i386 ont donné `0x56f5a8f8`, `0xd973ac1e` et `0x2358ebdb`.
- **n1low :** l'empreinte de la mémoire basse, écrite par le BIOS, est stable sous un émulateur donné mais diffère entre les deux machines.
- **Règle :** les deux cas appliquent la règle `nonzero` (empreinte différente de celle d'une page remise à zéro), satisfaite dans les deux cas.
- **Pages stables :** les cas de règle `same` (n1gdt, n1data, n1alloc, n3type, n3table) ont des empreintes **identiques** entre émulateurs.

Correction :
- la comparaison porte sur le statut et le nom ;
- chaque écart de mesure est **affiché** (`[INFO] mesure differente, A : … / B : …`) dans chaque rapport ;
- deux tests négatifs l'encadrent :
  - E7 « mesure seule différente » donne 0 **avec** la ligne `[INFO]` ;
  - E7 « statut différent sous une même mesure » donne 1.

## 10. Risques et limites restants

- **Étiquette non publiée** (§1) : la référence D-REF n'existe que localement tant que le développeur ne l'a pas poussée.
- **GDB sous `qemu-system-x86_64`** : `$eip`, le désassemblage et les arguments C symboliques sont faux. Une future vérification qui les utiliserait serait silencieusement fausse sous x86_64. Les deux protections sont la règle écrite dans `emu.sh` et `gdb_checks.sh`, et la comparaison des valeurs. Après le passage en mode long (M64-1 et suivants), l'architecture `i386:x86-64` deviendra au contraire la bonne ; le mode mixte, avec un trampoline 32 bits puis du code 64 bits, demandera une nouvelle expérience.
- **CPU non équivalents** (§4) : une réussite sous `qemu64` ne prouve rien pour `qemu32`, ni l'inverse, et aucune ne vaut pour du matériel réel (non testé).
- **Comparaison par verdicts :** deux bancs faux de la même manière sous les deux émulateurs ne divergent pas. La matrice détecte les **différences**, pas les erreurs communes ; celles-ci relèvent des tests négatifs et des mutations.
- **Mesures non comparées :** elles sont listées, mais pas jugées. Leur validité repose sur la règle de chaque cas.
- **SAMOS n'est pas déclaré sécurisé.** Ce jalon ne change aucune propriété du noyau.
