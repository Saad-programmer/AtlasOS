### Divergence relevée, puis traitée sans être masquée

La première exécution de la matrice a **échoué** :

```text
[FAIL] comparaison : DIVERGENCE entre build/emu/qemu-system-i386 et build/emu/qemu-system-x86_64
        < [PASS] n1low_page_intact (avant 0xd101c125, refus 0xfbe32763)
        > [PASS] n1low_page_intact (avant 0xcb942316, refus 0x9800a049)
        < [PASS] n1stack_page_intact (avant 0xd973ac1e, refus 0x770a88cb)
        > [PASS] n1stack_page_intact (avant 0x13975f42, refus 0x87a81bc6)
```

Analyse :
- **Verdicts :** ils sont identiques (`[PASS]`). La différence porte sur les **mesures** placées entre parenthèses.
- **n1stack :** l'empreinte de la pile active varie d'une exécution à l'autre **sous le même émulateur**. Trois exécutions i386 ont donné `0x56f5a8f8`, `0xd973ac1e` et `0x2358ebdb`.
- **n1low :** l'empreinte de la mémoire basse, écrite par le BIOS, est stable sous un émulateur donné mais diffère entre les deux machines.
- **Règle :** les deux cas appliquent la règle `nonzero` (empreinte différente de celle d'une page remise à zéro), satisfaite dans les deux cas.
- **Pages stables :** les cas de règle `same` (n1gdt, n1data, n1alloc, n3type, n3table) ont des empreintes **identiques** entre émulateurs.

Correction :
- la comparaison porte sur le statut et le nom ;
- chaque écart de mesure est **affiché** (`[INFO] mesure differente, A : … / B : …`) dans chaque rapport ;
- deux tests négatifs l'encadrent :
  - E7 « mesure seule différente » donne 0 **avec** la ligne `[INFO]` ;
  - E7 « statut différent sous une même mesure » donne 1.

### 10.3 Corrections, sans affaiblir aucune assertion

- **`tests/qemu/emu_compare.sh`**
  - Chaque côté est validé **seul** :
    - un bilan `QEMU:` unique, avec R = N, E = 0, et N lignes de verdict ;
    - un bilan `GDB:` unique, avec R = N, E = 0, et N lignes `[PASS] gdb:` ;
    - aucune ligne `[FAIL]` ni `[SKIP]` ;
    - `[TEST] skipped=` conforme à la table `SKIP_EXPECT` (recopie de `cases.sh` : `selftest_16M` = 1, dix autres journaux = 0 ; tout autre journal doit valoir 0) ;

## 12. Risques et limites restants

- **Étiquette non publiée** (§1) : la référence D-REF n'existe que localement tant que le développeur ne l'a pas poussée. *(Résolu : publiée par le développeur, §14.)*
- **GDB sous `qemu-system-x86_64`** : `$eip`, le désassemblage et les arguments C symboliques sont faux. Une future vérification qui les utiliserait serait silencieusement fausse sous x86_64. Les deux protections sont la règle écrite dans `emu.sh` et `gdb_checks.sh`, et la comparaison des valeurs. Après le passage en mode long (M64-1 et suivants), l'architecture `i386:x86-64` deviendra au contraire la bonne ; le mode mixte, avec un trampoline 32 bits puis du code 64 bits, demandera une nouvelle expérience.
- **CPU non équivalents** (§4) : une réussite sous `qemu64` ne prouve rien pour `qemu32`, ni l'inverse, et aucune ne vaut pour du matériel réel (non testé).
- **Comparaison par verdicts :** deux bancs faux de la même manière sous les deux émulateurs ne divergent pas. La matrice détecte les **différences**, pas les erreurs communes ; celles-ci relèvent des tests négatifs et des mutations.
- **Mesures non comparées :** elles sont listées, mais pas jugées. Leur validité repose sur la règle de chaque cas.
- **SAMOS n'est pas déclaré sécurisé.** Ce jalon ne change aucune propriété du noyau.
