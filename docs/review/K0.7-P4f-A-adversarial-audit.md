# K0.7-P4f-A — Audit contradictoire de la protection des structures critiques

**Nature :** audit de sécurité. **Aucun code de production n'a été modifié.** Le seul fichier ajouté au dépôt est ce rapport.
**Suivi :** D1 est corrigé par K0.7-P4f-B1 (`K0.7-P4f-B1-pmm-trust-boundary.md`) pour les structures de pagination et l'image du noyau. Une variante V2 (alias créé avant que le cadre ne devienne une table) a été découverte et corrigée dans le même jalon. D2, D3 et D4 restent ouverts.
**Base auditée :** commit `db420628` (P4e-2), branche `claude/k0.7-hardening` ; `main` = `95b9cb5` ; aucune PR ouverte ; stash existant non touché.
**Méthode :**
- relecture des documents P4a à P4e-2, sans tenir leurs conclusions pour acquises ;
- examen du code source, du linker et du code machine des images ELF (`objdump`, `nm`) ;
- validations complètes depuis un état propre ;
- **expériences jetables** dans une copie isolée du dépôt (`git archive` vers le répertoire temporaire de session, jamais intégrée ni poussée), pour contredire les invariants.

**Classes de preuve :**
- **PROUVÉ PAR TEST** : un test exécuté échoue si l'invariant est violé.
- **CONTRÔLÉ STATIQUEMENT** : un outil vérifie les sources ou le code machine.
- **INFÉRÉ** : conclusion tirée du code et de la documentation Intel, sans test qui la réfute.
- **NON TESTÉ** : aucune vérification.

**Une preuve obtenue sous QEMU n'est pas une preuve sur processeur réel.** §6 montre où les deux divergent pour ce noyau.

## 4. Audit de `pt_gate_write` (code machine, image de production)

### 4.1 Ce qui est vérifié

- **Provenance des adresses :** l'entrée écrite est calculée à partir de `g_pd` (lu dans `kro_vmm`, RO) et de l'index de `va`. Pour une PTE, l'adresse de la table vient du PDE (lui-même RO). L'appelant ne fournit jamais d'adresse. Code machine : `and $0xfffffffc,%esi; add 0x10d000,%esi` (`0x10d000` = `g_pd`).
- **Types PMM :** `pmm_core_type` est appelé pour le répertoire, la table, le cadre cible (`ALLOCATED` hors identité) et la règle `frame_is_pagetable`. **Toute** la validation dépend de `pmm->meta`, inscriptible (X3).
- **E1–E5 :** `va_must_stay_unmapped` est compilé en comparaisons immédiates sur les adresses des gardes (`0x18f000`, `0x191000`, `0x196000`) et sur la page nulle. `vmm_map` garde ses propres contrôles en premier.
- **Références :** le passage n'en manipule aucune. `map_page` les rend en cas de refus ; X4 montre `refs(g)=0` après un échec de `table_create`.
- **Fenêtre** (adresses `0x10149d`-`0x1014ce`) :
  ```
  pushf; pop %ecx; cli
  movl $1, g_pt_gate_active
  and $0xfffeffff,%edx; mov %edx,%cr0
  mov %esi,(%edi)          ; seule instruction entre les deux CR0
  mov %eax,%cr0
  movl $0, g_pt_gate_active
  test $0x200,%ecx; je; sti
  ```
  Aucun appel, aucun saut, aucune sortie entre les deux écritures de CR0. Les sorties anticipées (refus) sont toutes **avant** `cli`.
- **Barrières du compilateur :**
  - `cpu_write_cr0`, `cpu_cli` et `cpu_sti` portent le clobber `memory` ;
  - `g_pt_gate_active` et l'entrée sont `volatile` ;
  - l'ordre stockage/CR0 est donc imposé au compilateur, et le code machine le confirme.
  - En revanche, `cpu_read_cr0` n'a **pas** de clobber `memory`. Ce n'est pas un défaut ici (asm `volatile`, ordre entre asm volatiles conservé), mais il faut le noter si la fonction est réutilisée ailleurs.

### 4.2 Constats

1. **Validation avant le masquage des IRQ** (`pt_gate_check` puis `irq_save`).
   - La décision et l'écriture ne sont pas faites sous la même section critique.
   - Un gestionnaire d'IRQ qui modifierait le PMM ou le VMM entre les deux rendrait la validation caduque, par exemple en libérant un cadre.
   - **Non atteignable aujourd'hui :** aucun gestionnaire n'utilise le VMM ou le PMM (`grep` sur `pit.c`, `ps2kbd.c`, `irq.c` : aucun appel). Cette hypothèse n'est pas imposée par le code.
2. **CR0 lu avant `cli`** (`mov %cr0,%eax` en `0x10143f`, `cli` en `0x10149f`). La valeur rétablie est un instantané pris IRQ actives. Un gestionnaire qui changerait CR0 (par exemple TS, avec une future FPU paresseuse) verrait sa modification annulée. Non atteignable aujourd'hui.
3. **Politique PDE trop large (X2) :**
   - un PDE présent peut être écrasé ;
   - deux PDE peuvent désigner la même table ;
   - aucun INVLPG ne couvre la région de 4 MiB ;
   - et le passage ne peut ni effacer ni corriger un PDE : la valeur doit être exactement P | W, ce qui exclut aussi un PDE portant le bit A.

   **Les PTE hors identité** peuvent aussi être écrasées alors qu'elles sont présentes (relu dans le code : aucune condition « entrée absente »). `map_page` vérifie EEXIST avant, mais le passage ne l'impose pas.

### 4.3 Fautes dans la fenêtre

| Événement | Analyse | Classe |
|---|---|---|
| **#PF synchrone sur `mov %esi,(%edi)`** | L'entrée se trouve dans une table de l'identité, toujours présente ; avec WP = 0, aucune faute de protection. Une #PF exigerait une table hors identité (impossible : tous les cadres du PMM sont sous `g_idmap_top = nframes << 12`, relu dans `mm.c`). | INFÉRÉ |
| **#GP sur `mov cr0`** | La valeur dérive de la valeur courante, seul WP est changé : aucun bit réservé. | INFÉRÉ |
| **#DB** | Seulement si EFLAGS.TF ou DR7 sont actifs ; le noyau n'utilise ni l'un ni l'autre. Avec un débogueur (GDB pas à pas), le gestionnaire #DB s'exécuterait avec WP = 0. | INFÉRÉ |
| **NMI** | Non masquée par `cli`. Le vecteur 2 n'a pas de gestionnaire enregistré : panique déterministe (testé au repos, §1). Dans la fenêtre, la panique s'exécuterait avec WP = 0, puis arrêt. Aucune source NMI n'est programmée. Injection **dans** la fenêtre : 3 instructions, irréalisable sans instrumentation. | panique : PROUVÉ PAR TEST (hors fenêtre) ; dans la fenêtre : **NON TESTÉ** |
| **#MC** | CR4 = 0 (relevé par le moniteur), donc CR4.MCE = 0 : une erreur machine met le processeur à l'arrêt (*shutdown*, SDM vol. 3B ch. 15). Arrêt brutal, sans gestionnaire. | INFÉRÉ |
| **SMI** | SMM sauve et rétablit CR0 : transparent pour le noyau. | INFÉRÉ |

**La fenêtre n'est pas « atomique » au sens fort.** Elle est courte (une instruction), ininterruptible par les IRQ, et sans appel. Une NMI, un #MC ou une #DB peuvent toutefois s'y insérer. Aujourd'hui, toutes ces voies aboutissent à un arrêt, sauf #DB sous débogueur.

## 5. Cycle de vie des tables

```
FREE ─pmm_core_alloc_as(PAGETABLE)─▶ PAGETABLE (alias RW, non publiée)
     ─memset (alloc_zeroed)────────▶ initialisée (alias RW, non publiée)
     ─seal_table_frame─────────────▶ scellée (alias RO, INVLPG)      [sous PG]
     ─pt_gate_write(PDE)───────────▶ publiée (RO)
     ─pt_gate_write(PTE) / MMU A,D─▶ utilisée (RO)
     (aucune transition de sortie : jamais libérée, jamais retypée)
```

Au démarrage (PG = 0), l'ordre est différent : publication, puis scellement en bloc juste après PG | WP. Aucun code non fiable ne s'exécute entre les deux.

### Chemins d'échec

| Échec | État laissé | Atteignable hors mutation ? |
|---|---|---|
| `pmm_alloc_pagetable` → 0 | rien | **oui** (mémoire épuisée) ; ENOMEM correct |
| `seal_table_frame` refusé | cadre `PAGETABLE`, **alias RW**, non publié | **non** dans l'état actuel : il faudrait `g_pt_gate_active` = 1, WP absent, CR3 ≠ `g_pd` ou un alias d'identité absent, ce qui suppose un défaut ou une corruption préalable (INFÉRÉ) |
| PDE refusé après scellement | cadre `PAGETABLE`, alias RO, non publié | **non** (mêmes conditions) |
| `pmm_ref` → ERANGE après création | table **publiée**, vide | **oui** (4 095 références) ; la table reste utilisable (M2.4c), ce n'est pas une fuite |

### Réponses aux questions posées

- **Le défaut est-il atteignable hors mutation ?** Non, dans l'état actuel du code (INFÉRÉ). Il l'est par le crochet de test `paging_gate_test_set_active` (X4) et deviendrait atteignable si un gestionnaire d'interruption utilisait un jour le passage.
- **Les références PMM deviennent-elles incohérentes ?** Non : aucune référence n'est prise avant `table_create` (X4 : `refs(g)=0`). `pmm_core_check` reste cohérent, puisque le cadre est un `PAGETABLE` valide sans référence.
- **La mémoire est-elle définitivement perdue ?** Oui : un cadre par échec, sans chemin de récupération (X4 : un second cadre consommé au nouvel essai).
- **Un rollback sûr est-il possible ?** Pas sans ajouter deux chemins privilégiés : retrait de W de l'alias **interdit** par le passage (sens unique), puis transition `PAGETABLE → FREE` **interdite** par le PMM. Les ajouter élargirait la surface d'attaque au profit d'un cas qui signale déjà une incohérence interne. Sans rollback, le cadre non scellé (premier cas) reste un `PAGETABLE` RW non publié, qu'un PDE fautif (X2) pourrait publier inscriptible.
- **Faut-il paniquer plutôt que renvoyer une erreur ?** **Oui, recommandé.**
  - L'échec n'est possible que si un invariant du noyau est déjà rompu.
  - Le code d'erreur actuel (EBUSY, EPERM) est indiscernable, pour l'appelant de `vmm_map`, d'un refus légitime de **sa** requête.
  - C'est aussi la règle de `paging_init` (panique sur tout échec de scellement).
  - Pour garder la testabilité, ce chemin serait couvert par un cas QEMU attendant la panique, plutôt que par une assertion.

## 6. TLB et bits A/D

| Point | Architecture (Intel SDM vol. 3A) | Ce noyau | Couvert par |
|---|---|---|---|
| INVLPG | invalide les entrées du TLB **et** des caches de structures de pagination pour la page (§4.10.4.1) | après chaque écriture acceptée sous PG, sauf la publication d'un PDE auparavant absent | sources ; `check_elf` (scellement seulement) |
| Écriture d'une PTE ou d'un PDE | **n'invalide rien** ; une traduction périmée peut subsister (§4.10.4.1, §4.10.4.3) | — | X1-contrôle : périmée sous QEMU |
| Entrée non présente | jamais mise en cache (§4.10.2.3, §4.10.3.1) | justifie l'absence d'INVLPG après la publication d'un PDE absent | INFÉRÉ |
| MOV vers CR0 | invalide le TLB **seulement** si PG passe de 1 à 0 (§4.10.4.1) ; un changement de WP **n'est pas** listé | — | — |
| **QEMU** | vide tout le TLB à **tout** changement de PG, WP ou PE (`cpu_x86_update_cr0`) | chaque fenêtre du passage vide le TLB | **X1 : confirmé** |
| Bits A/D | écrits par le MMU par accès physique aux structures de pagination, indépendamment des droits de leur alias (§4.8) | tables RO dans l'identité | `test_ptseal` (QEMU) |

**Conséquences :**

1. Sous QEMU, **aucun test d'exécution ne peut prouver un INVLPG** qui suit une fenêtre du passage. Or toutes les modifications de PTE en passent par une. Les assertions « INVLPG effectif » de P4c (`test_ptgate.c`) et le commentaire « vérifié par autotest » de `vmm_unmap` (`paging.c`) sont **devenus inexacts** depuis P4e-1 (X1-bis : la suppression de cet INVLPG n'est plus détectée).
2. **Sur un processeur réel**, les INVLPG de `vmm_unmap`, `map_page` et `seal_table_frame` sont nécessaires. Leur absence n'est surveillée que pour `seal_table_frame` (code machine). **Le contrôle du code machine n'est pas une validation sur matériel.** Il prouve la présence de l'instruction, pas son effet.
3. **Perte de bits A/D :** `seal_table_frame` lit la PTE avant la fenêtre (IF éventuellement à 1), puis réécrit `pte & ~W`. Un bit A ou D posé entre la lecture et l'écriture serait perdu. Sans conséquence aujourd'hui (aucun usage de A/D par le noyau) ; à revoir si A/D servent un jour (pagination sur disque).

### 8.2 Hypothèses non vérifiées

- **H1 :** aucun gestionnaire d'interruption ou de NMI n'utilise le VMM ou le PMM, ni ne modifie CR0. Vrai aujourd'hui (`grep`), mais imposé par aucun code.
- **H2 :** sur processeur réel, INVLPG, les bits A/D sur des tables RO et l'absence de vidage du TLB par CR0.WP se comportent comme le décrit le SDM. **NON TESTÉ** sur matériel.
- **H3 :** aucune source NMI ; CR4.MCE = 0 donne un *shutdown* plutôt qu'un gestionnaire.
- **H4 :** aucun code n'est exécuté depuis des données (pas de NX). C'est hors de P4.
- **H5 :** d'après le SDM (vol. 3A §7.4), la commutation imbriquée vers la tâche #DF écrit le *previous task link* dans le TSS #DF et l'état dans le TSS sortant, et pose le bit *busy* dans la GDT. Le TSS #DF et la GDT doivent donc rester au moins partiellement RW. **NON TESTÉ** au-delà du triple fault documenté en P4a.

### 8.3 Limites des tests

- Toutes les preuves d'exécution viennent de QEMU 8.2 (TCG), sans KVM ni matériel.
- Les assertions de TLB qui suivent une fenêtre du passage ne prouvent rien (§6).
- L'audit de production ne s'exécute qu'au démarrage.
- Les modes destructifs vérifient la faute, pas l'absence d'autres alias (c'est l'audit qui le fait, et il dépend du PMM).
- Les mutations n'injectent qu'un défaut à la fois ; les enchaînements (X4 + X2) ne sont couverts par aucune.

## 9. Corrections recommandées (non implémentées)

**Obligatoires avant la clôture de P4 (proposition de P4f-B) :**

1. **D1 :** rendre la protection des cadres de pagination **indépendante du PMM**. `vmm_map` et le passage refusent tout cadre égal à `g_pd` ou désigné par un PDE présent (lecture du répertoire RO). L'audit applique la même règle sans `pmm_core_type`. Cela ne protège pas encore l'IDT et `.text` contre D1 ; pour ceux-ci, il faut décider de sceller `meta` ou d'accepter et documenter le risque (décision du développeur).
2. **D2 :**
   - règle `check_elf` « INVLPG après l'appel de `pt_gate_write` » pour `map_page` et `vmm_unmap` (fonctions rendues non inlinées, comme `seal_table_frame`) ;
   - mutations `mutant_tool` correspondantes ;
   - correction du commentaire de `vmm_unmap` et des assertions « INVLPG effectif » de `test_ptgate.c` ;
   - mention explicite de la limite de QEMU.
3. **D3 :** politique stricte du passage : PDE absent avant écriture, table désignée par aucun autre PDE ; PTE hors identité : création seulement sur une entrée absente.
4. **D4 :** panique sur échec interne de `table_create`, avec un cas QEMU attendant la panique (statut 37).

**Recommandées :**

5. **D5 :** `irq_save` avant la validation ; CR0 lu sous `cli`.
6. **D6, D7 :** corriger P4d §2 et écrire les hypothèses de P4e-2 (PMM intègre, appelants conformes).
7. **7.13 :** audit à chaque création de table (coût : 1 024 PDE plus le parcours des tables).
8. **7.12 :** protéger ou relocaliser `g_pt_gate_active`.

**Décisions du développeur à prendre (architecture) :**

- **GDT/TSS (7.2) :** accepter le risque documenté, ou découper la GDT et étudier le TSS #DF.
- **Table PMM (7.1) :** la sceller avec un passage dédié, ou accepter le risque.
- **NMI (7.5) :** ajouter un gestionnaire minimal qui rétablit WP, ou accepter le risque.
- **Matériel réel (7.9) :** campagne sur machine physique ou KVM.

## 10. Critères objectifs de clôture de P4

P4 pourra être clôturé quand **tous** les critères suivants seront remplis et vérifiés par les commandes de §1 :

1. Les défauts D1 (au moins pour les cadres de pagination), D2, D3 et D4 sont corrigés, et chacun est couvert par une mutation détectée par assertion nommée ou par diagnostic d'outil.
2. Les expériences X2, X3 (restreinte aux tables), X1-bis et X1-ter, rejouées, sont **refusées** ou **détectées**.
3. Les risques 7.1 (cadres non pagination), 7.2, 7.5 et 7.6 sont soit corrigés, soit **explicitement acceptés par le développeur** dans un document de clôture.
4. La documentation (P4d, P4e-2, `paging.c`) ne contient plus d'affirmation de test inexacte (D2, D6, D7).
5. Les validations de §1 passent à l'identique depuis un état propre.
6. La différence QEMU / matériel (§6) figure dans la clôture, avec la liste de ce qui reste **NON TESTÉ** sur matériel.

## 11. Conclusion

**2. P4 nécessite un P4f-B de corrections ciblées.**

**Pas de problème architectural bloquant.** La fenêtre CR0.WP, l'ordre de scellement et le cycle de vie des tables sont cohérents. Les protections annoncées sont effectives sous les hypothèses énoncées : PMM intègre, appelants conformes, monoprocesseur, et absence de NMI ou de #MC dans la fenêtre.

**Mais l'audit a confirmé plusieurs défauts** :
- **D1 :** une écriture de données de 16 bits contourne P4d et P4e-2 ;
- **D2 :** la preuve des INVLPG du VMM a disparu depuis P4e-1 ;
- **D3 et D4 :** la politique du passage et le chemin d'échec de `table_create` sont trop permissifs.

Tous se corrigent de façon ciblée, sans changer l'architecture, à condition que le développeur tranche les décisions de §9 (GDT/TSS, table PMM, NMI).

**Arrêt après P4f-A :** aucune correction implémentée, K0.7 non clôturé, K1 non commencé.
