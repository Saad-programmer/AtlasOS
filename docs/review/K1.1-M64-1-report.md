# K1.1-M64-1 — Construction double i386 / x86-64

- **Statut :** réalisé sur la branche `claude/k1.1-m64-1-build`, **en attente de l'audit du développeur**. Rien n'est intégré dans `main`.
- **Point de départ :** `main` = `origin/main` = `5370fe598877c912d1d5c951ad2917f938d4301a`.
- **Ce que signifie la réussite :** les deux architectures disposent d'une **chaîne de construction contrôlée**. **SAMOS n'exécute aucun code 64 bits.** Le squelette ELF64 n'est **pas amorçable** et n'est démarré par aucun banc.
- **Hors périmètre (M64-2 et suivants, non autorisés) :**
  - tremplin, mode long, PAE, EFER, NX ;
  - tables de pages, GDT64 et IDT64 ;
  - en-tête ou chargement Multiboot (A-1) ;
  - portage du PMM, du VMM, des interruptions et de l'ordonnanceur.

### 3.1 Drapeaux x86-64 (`mk/x86_64.mk`)

- **C :**
  - cible et base : `--target=x86_64-unknown-none-elf -march=x86-64 -std=c11` ;
  - environnement : `-ffreestanding -nostdlibinc -fno-pic -fno-pie` ;
  - propres au noyau x86-64 : `-mno-red-zone -mgeneral-regs-only -mcmodel=small` ;
  - durcissement : `-fstack-protector-strong -fcf-protection=none` ;
  - débogage et cadre : `-fno-omit-frame-pointer -fno-asynchronous-unwind-tables -fno-unwind-tables -fno-common -O2 -g` ;
  - avertissements : ceux de l'i386, avec `-Werror` ;
  - autres : `-Wframe-larger-than=3072 -ffile-prefix-map`.
- **NASM :** `-f elf64 -g -F dwarf -w+all -w+error`.
- **`ld` :** `-m elf_x86_64 -T kernel/arch/x86_64/linker.ld -nostdlib -z max-page-size=0x1000 -z noexecstack --build-id=none --fatal-warnings`.

### 3.2 Règles ELF64 (`tools/check_elf64.sh`)

| Règle | Contrôle |
|---|---|
| X1-X3 | ELF64 little-endian, x86-64, EXEC |

| X5 | **aucun** magic Multiboot 1 (`0x1BADB002`) ni 2 (`0xE85250D6`) dans les 32 premiers KiB : image non présentée comme amorçable |

## 5. Défauts trouvés pendant M64-1 et corrections

1. **Analyse des colonnes de `readelf`.** Dans `check_elf64.sh` (première version), les drapeaux de section sont dans la colonne 7, et ceux des segments commencent à la colonne 7. Le vérificateur refusait des images correctes. Corrigé avant tout résultat retenu.
2. **X8 aveugle à un symbole indéfini.** Le test N6 (symbole indéfini, liaison forcée par `--unresolved-symbols=ignore-all`) a été **accepté** par X8. GNU ld résout ce symbole, ainsi qu'un symbole indéfini faible, à 0, et le **retire** de la table des symboles de l'exécutable statique ; aucun contrôle de l'image ne peut alors le voir. Correction :
   - contrôle sur les **objets d'entrée** (L0 à L2) ;
   - interdiction des options de `ld` qui le permettent (F7) ;
   - limite documentée dans X8.
   N6 a été retiré des tests sur image, car le défaut n'y est pas représentable.
3. **Expression régulière de F7.** Elle exigeait une espace après `=`, si bien que F7 était accepté ; corrigé.
4. **Espace de travail des tests.** Placé d'abord dans `build/x86_64/selftest`, il était exclu de l'analyse, et S1 ne trouvait aucun objet. Après son déplacement, **S0 a détecté à juste titre** l'objet i386 laissé par l'exécution précédente dans `build/x86_64`. Ce répertoire généré a été supprimé, et l'espace de travail est désormais `build/tests/x86_64_build`.

## 8. Risques et limites

- **Le squelette n'est pas représentatif d'un noyau.** Il contient deux fonctions et trois objets. Les contrôles prouvent la chaîne de construction, pas le comportement de code 64 bits.
- **Hypothèses locales :** l'adresse de 1 MiB et `-mcmodel=small` devront être revues par D-LAYOUT et A-6. X12 et X9 sont des règles **de M64-1** ; elles changeront alors.
- **X11 est une analyse de motifs du désassemblage**, pas une preuve. Un octet `0x0F 0x30` (`wrmsr`) caché dans des données ne serait pas vu, puisque seul le code désassemblé est analysé.
- **X5 cherche les magic alignés sur 4 dans les 32 premiers KiB.** Ce sont les zones de recherche de Multiboot 1 (8 KiB) et 2 (32 KiB) ; un magic placé plus loin n'est pas visé, car il serait ignoré par un chargeur.
- **Contrôle du symbole indéfini** : il porte sur les objets d'entrée connus (`build/x86_64/{prod,test}`). Une bibliothèque ajoutée plus tard à la liaison devra y être incluse.
- **Mutations :** les 91 mutations i386 ont été exécutées **localement uniquement**. Le job manuel GitHub n'a pas été déclenché. Aucune mutation ne vise encore la chaîne x86-64 : les tests négatifs en tiennent lieu.
- **Matériel réel :** non testé. SAMOS n'est pas déclaré sécurisé.
