# K0.7-P4f-B3 — Intégrité transactionnelle de la création des tables (correction de D4)

**Périmètre :** défaut D4 de l'audit P4f-A et conséquences directes de sa correction. D2, P4f-C et K1 ne sont **pas** traités.
**Base :** commit `fca1f654` (P4f-B2) ; `main` = `95b9cb5` ; aucune PR ; stash existant intact.

## 1. Reproduction de D4 (copie isolée, avant correction)

Image de test, 128 MiB, commit `fca1f654`. Le refus du PDE a été injecté par une variable ajoutée **dans la copie seulement**. Mesures après chaque `vmm_map` vers une région sans table :

| Cas | Atteignable ? | Retour | Cadre candidat : type, refs, identité | Cadres libres | PDE | Tables publiées |
|---|---|---|---|---|---|---|
| 1. allocation impossible (épuisement **réel**, 32 268 cadres pris) | **oui** | −2 (ENOMEM) | aucun | inchangé (0 → 0) | absente | inchangé |
| 2. initialisation impossible (table publiée marquée FREE : `test=pdesteal`) | non : PMM falsifié | — (#PF code 3 dans la remise à zéro, panique) | la table publiée, identité RO | — | — | — |
| 3. scellement refusé (passage occupé : crochet de test) | non : injection | −9 (EBUSY) | `0x001d7000` PAGETABLE, refs 0, identité **`…063` (W)** | **−1, cadre perdu** | absente | inchangé ; audit `unpublished=1` |
| 4-5. passage / PDE refusé après scellement (injection) | non : injection | −10 (EPERM) | `0x001da000` PAGETABLE, refs 0, identité `…061` (RO) | **−1, cadre perdu** | absente | inchangé ; `unpublished=2` |

**Constats :**
- les échecs 3 à 6 rendaient un code **ordinaire** (EBUSY, EPERM) alors que le noyau avait **définitivement perdu un cadre** ; dans les cas 3 et 6, ce cadre restait **inscriptible** ;
- l'appelant de `vmm_map` ne pouvait pas distinguer « votre requête est refusée » de « un invariant du noyau est rompu » ;
- **le cas ERANGE est atteignable sans aucune injection :** une erreur ordinaire laissait un effet de bord (une table publiée et un cadre consommé).

## 2. Cause racine

`table_create` faisait suivre la seule étape faillible pour une raison ordinaire (l'allocation) d'étapes qui ne peuvent échouer que si un invariant est déjà rompu : un alias préexistant, une structure redistribuée, un scellement ou une publication refusés par le passage. Elle les traitait pourtant toutes de la même façon, en **renvoyant l'erreur**. Or une fois alloué, le cadre est `PAGETABLE` :
- il n'est jamais libérable : `pmm_free_frame` refuse tout autre type qu'ALLOCATED ;
- le rendre exigerait de rétablir W sur son alias, ce que le passage interdit (sens unique, P4e-2), puis une transition `PAGETABLE → FREE` que le PMM ne connaît pas.

**Aucun retour arrière n'existe ; l'erreur ordinaire était donc mensongère.**

Par ailleurs, `map_page` ne vérifiait la capacité de références qu'**après** `table_create` (`pmm_ref` est « la dernière étape faillible »). Le refus ERANGE arrivait donc après la création de la table.

## 3. Politique retenue

### 3.1 Erreurs ordinaires : code exact, aucun effet

Toutes sont rendues **avant** `table_create`, sauf ENOMEM, qui est rendue par `table_create` avant toute modification.

| Erreur | Code | Lieu |
|---|---|---|
| paramètres invalides (va ou pa non alignée, droits hors {0, W}) | EINVAL | `map_page`, premier contrôle |
| projection interdite : page nulle et gardes (E1/E2), cadre non ALLOCATED (M2.5b), image ou structure de pagination (P4f-B1) | EPERM | `map_page` |
| **références saturées** | ERANGE | `map_page`, **nouveau pré-contrôle avant la création de la table** |
| mémoire insuffisante | ENOMEM | `table_create`, avant tout effet |
| région déjà utilisée | EEXIST | `map_page` ; ne peut survenir que dans une table **existante** (une table neuve est vide) |

`pmm_ref` reste vérifié après la création, par défense : en monoprocesseur, sans gestionnaire d'IRQ qui prenne de référence, il ne peut plus échouer après le pré-contrôle.

### 3.2 Violations d'invariant après l'allocation : panique contrôlée

`table_create_fatal(step, err, va, frame)` est `SAMOS_NORETURN`. Elle appelle `panic` avec un diagnostic complet :

```
page-table creation: <étape> (error <e>) for va <va>: frame <f> type <t> identity PTE <pte>, PDE <pde>;
kernel invariant violated, frame not returned
```

| Étape | Déclencheur réel | Mode de test |
|---|---|---|
| `frame already mapped elsewhere` | le PMM distribue un cadre encore projeté hors identité (PMM falsifié, V2) | `test=tablealias` |
| `frame already a paging structure` | le PMM distribue une table publiée (PMM falsifié) | inatteignable : la remise à zéro faute avant (`test=pdesteal`) |
| `sealing refused` | le passage refuse de sceller un cadre qu'il vient de recevoir (passage occupé, WP absent, type de la table d'identité falsifié…) | `test=tcseal` |
| `PDE publication refused` | le passage refuse un PDE que le noyau vient de valider | `test=tcpde` (injection) |

La panique est **déterministe** :
- aucune écriture n'a lieu entre le refus et l'arrêt ;
- le cadre est laissé tel quel (PAGETABLE, non publié) ;
- aucun code n'est rendu au VMM.

Dans `paging_init` (pagination inactive), ces étapes sont aussi fatales. ENOMEM reste rendu : `mm_init` échoue et `kmain` panique (« memory management initialisation failed (-2) »), comme avant.

### 3.3 Aucun mécanisme de libération ajouté

Aucun retour arrière, aucune requalification, aucune libération de table n'a été introduit. Un retour arrière sûr exigerait un **nouveau chemin privilégié** (désceller l'alias, transition PAGETABLE → FREE). Ce chemin pourrait libérer une table, réutiliser un cadre projeté, réintroduire un alias RW, et contournerait D1 et D3. C'est un changement d'architecture (§7).

## 4. Intégrité des transitions

| Transition | Préconditions | Modifications | Effets de bord possibles | Erreurs autorisées | Invariants préservés |
|---|---|---|---|---|---|
| **FREE → PAGETABLE** (`pmm_core_alloc_as`) | `free_count > 0` | type posé **avant** que le cadre quitte le PMM ; `free_count − 1` ; `hint` | aucun sur la pagination | ENOMEM (aucun effet) | aucun instant où une table serait ALLOCATED |
| **→ initialisée** (`alloc_zeroed`, `memset` par l'identité) | identité du cadre **inscriptible** (cadre libre) | 4 KiB à zéro | si le cadre est en fait une structure publiée (PMM falsifié) : #PF sur l'identité scellée, **panique** | aucune | une table publiée n'est jamais remise à zéro |
| **→ contrôlée** | sous PG : aucun alias hors identité ; dans tous les cas : pas déjà structure | aucune | aucun | **aucune : panique** | D1 (pas d'alias), D3 (unicité) |
| **→ scellée** (`seal_table_frame`) | sous PG ; type PAGETABLE ; identité exacte présente | identité : W retiré (fenêtre WP), INVLPG | — | **aucune : panique** | table jamais inscriptible une fois publiée |
| **→ publiée** (PDE par le passage) | PDE absente ; cible non structure, scellée, sans alias (contrôles du passage, P4f-B2) | une PDE (fenêtre WP) ; `g_tables + 1` | — | **aucune : panique** | ensemble des cibles à croissance seule, sans doublon |
| **utilisée** | — | PTE par le passage ; A/D par le MMU | — | erreurs ordinaires des projections (§3.1) | table publiée **scellée, unique, sans alias RW** (audit) |

### 5.2 Modes destructifs (statut 37, cas QEMU)

| Mode | Diagnostic exigé | Contrôles |
|---|---|---|
| `tcseal` | `page-table creation: sealing refused (error -9)` | `kernel invariant violated, frame not returned` ; pas de « NOT fatal », pas de panique récursive, pas de double faute |

Si `vmm_map` **revenait**, chaque mode afficherait `[TEST] internal violation NOT fatal (vmm_map returned …)` et le cas échouerait. Aucun test ne déréférence la table après l'échec de sa création : le noyau s'est arrêté.

**Variante V2 :** elle sort de la suite `test=pmmtrust`, puisque son refus est désormais fatal, et devient le mode `tablealias`. Le mode `pmmtrust` signale maintenant `refused_existing_region` et `gate_refused` **avant** la sonde « région sans table », dont la falsification mènerait à une création de table fatale si un contrôle disparaissait.

## 6. Mutations

**Moteur :** nouvelle forme `mutant_mode NOM FICHIER ORIG MUTÉ MODE STATUT DIAGNOSTIC…`, pour les modes destructifs. La mutation est **détectée** seulement si :
- le statut obtenu est celui attendu, 35 ou 37 (jamais 124, un arrêt CPU ou un triple fault) ;
- chaque diagnostic exact figure dans le journal du noyau muté ;
- **aucun** de ces diagnostics ne figure dans celui de la version saine du même mode.

Deux nouvelles situations d'auto-test le vérifient : `mode_shared` (diagnostic aussi présent dans la version saine) et `mode_status` (statut 124 refusé). Le moteur compte maintenant 15 situations.

| Mutation | Défaut | Détection |
|---|---|---|
| M47 `tl_erange_precheck_removed` | effet de bord avant un refus (table créée avant ERANGE) | `erange_no_table_created` |
| M48 `tc_pde_fatal_to_return` | violation interne → retour ordinaire (PDE) | `tcpde`, statut 35 : `internal violation NOT fatal` |
| M49 `tc_seal_fatal_to_return` | idem (scellement) | `tcseal`, statut 35 : idem |
| M50 `tc_alias_fatal_to_return` | idem (cadre aliasé) | `tablealias`, statut 35 : idem |
| M51 `seal_keeps_write` | table non scellée : le scellement ne retire plus W | statut 37 : `memory management initialisation failed (-10)`. Le passage refuse de poser W sur une structure : le scellement en bloc de `paging_init` échoue au démarrage |
| M52 `tl_enomem_check_removed` | contrôle d'erreur supprimé (épuisement non reconnu) | statut 37 : `page-table creation: sealing refused (error -1)` |

**Mutations antérieures converties.** Leurs défauts mènent désormais à un arrêt contrôlé, donc la forme `mutant` (statut 35) ne s'applique plus :
- **M30 `seal_new_table_removed` :** mode `pdeint`, `PDE publication refused`.
- **M39 `pmmtrust_prior_alias_ignored` :** mode `tablealias`. Le cadre volé est scellé, puis sa publication refusée : l'arrêt est plus tardif et le diagnostic différent de celui de la version saine.
- **M34 `pmmtrust_map_check_removed` et M37 `pmmtrust_directory_ignored` :** mode `pmmtrust`, `sealing refused`. La requête interdite atteint une création de table ; le passage refuse alors d'écrire dans la table ou le répertoire dont le type PMM est falsifié.
- **M36 `pmmtrust_pde_targets_ignored` :** assertion nommée `refused_existing_region` **et** diagnostic `sealing refused`.

**Bilan :** 52 mutations, 52 détectées.

## 9. Limites et conséquences pour une future libération des tables

- **Un PMM falsifié peut provoquer un arrêt :** retyper la table d'identité ou le répertoire fait refuser le scellement de la table suivante, ce qui est fatal. C'est un déni de service par refus fermé, cohérent avec « incohérence grave PMM/VMM ⇒ panique ». Avant P4f-B3, le même cas rendait EPERM en perdant un cadre.
- **Les tables restent conservées jusqu'à l'arrêt.** Une table vidée reste publiée ; un échec fatal ne rend rien.
- **Une future libération des tables** (K1 : espaces d'adressage multiples) exigera un **chemin privilégié dédié** et justifié, dans cet ordre :
  1. vider la table ;
  2. retirer le PDE, ce qui demande une exception explicite à la règle d'écriture unique de D3, limitée à ce chemin ;
  3. invalider la région de 4 MiB, avec un *shootdown* en SMP ;
  4. vérifier l'absence d'alias, sans le PMM ;
  5. rétablir W sur l'identité (exception à la règle à sens unique) ;
  6. effacer le contenu ;
  7. effectuer la transition PAGETABLE → FREE, aujourd'hui inexistante.

  Chaque étape devra être fatale en cas d'incohérence, comme ici.
- **La panique est une terminaison sûre mais brutale :** il n'y a aucune reprise. Toute politique de récupération (par exemple réserver une table d'avance pour ne jamais échouer après une allocation) relève d'un jalon futur.
- **`pmm_ref` après la création reste un chemin d'erreur ordinaire** (défense). Il est inatteignable en monoprocesseur après le pré-contrôle ; en SMP, il faudrait verrouiller.
- **Inchangés :** D2 (INVLPG du VMM non prouvés sous QEMU), GDT/TSS, NMI/#MC, références falsifiées (E5 sous corruption), multiprocesseur.

**D4 est corrigé pour son périmètre.** D2 reste ouvert : P4 n'est pas clôturé.
