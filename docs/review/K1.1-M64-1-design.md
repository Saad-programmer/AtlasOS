- **Nature :** document de conception **seulement**. Il ne contient aucun code de production, aucun tremplin, aucune table de pages, et ne modifie ni les tests ni la CI.
- **Base :** `main` = `origin/main` = `92b1880b34f572526bb70001ef78230c3b0eef16`. Branche : `claude/k1.1-m64-1-design`.
- **Référence i386 :** étiquette `ref/i386-k0.7`, objet `f671c13658c7cedff81c96ad4186013b54063256`, cible `7e43b786cc049e112b19e1ad786c15df6c4aeba9`.

  - D1 = B : migration avant `kmalloc`, l'ordonnanceur et les processus ;

## 2. Note de numérotation, soumise à arbitrage

Dans `K1.1-design-review.md` §7, **M64-1** désigne la *construction double* (`ARCH=x86_64` à côté de `ARCH=i386`, squelette qui se lie). **M64-2** y désigne le *tremplin vers le mode long*.

Le présent document, demandé sous le nom M64-1-DESIGN, spécifie le **contrat du tremplin**, donc le contenu de M64-2, ainsi que ses prérequis de construction (M64-1). Je propose de le considérer comme la conception commune de M64-1 et M64-2, sans renuméroter le plan. Décision **A-0** au §12.

Constats :
- **Aucune instruction `CPUID`** n'existe dans le noyau : grep `cpuid|EFER|PAE|NX` vide hors commentaire de `paging.h` [code].
- `rdtsc` est utilisé sans vérifier `CPUID.01H:EDX.TSC` : le noyau suppose un i586 ou plus. C'est sans conséquence en x86-64, où TSC est toujours présent [spec], mais c'est une hypothèse implicite.
- Les refus précoces (`.halt`) sont **silencieux** : aucun message avant `kmain`.

### 3.2 Script de liaison — `kernel/arch/i386/linker.ld`

- `OUTPUT_FORMAT("elf32-i386")` (l. 25), `OUTPUT_ARCH(i386)`, `KERNEL_LOAD_ADDR = 0x00100000` (l. 29) : identité, adresse virtuelle = adresse physique.
- Trois `PHDRS` : `text` R-X, `rodata` R--, `data` RW-. `check_elf.sh` refuse tout segment W+X et exige vaddr = paddr ≥ 1 MiB.
- `.bss` commence par les pages critiques, chacune alignée et d'exactement une page :
  - `__kcpu_*` : GDT et 2 TSS, laissées RW ;
  - `__kro_idt_*` : IDT ;
  - `__kro_handlers_*` : tables de gestionnaires ;
  - `__kro_vmm_*` : `g_pd`, `g_idmap_top`.
- `.stacks` (NOLOAD, ni chargée ni remise à zéro), de bas en haut :
  - garde S2 (`__df_guard_*`, 4 KiB) ;
  - S2 (`df_stack_area`, 4 KiB) ;
  - garde basse S1 (`__stack_guard_*`) ;
  - S1 (`boot_stack_bottom` … `boot_stack_top`, 16 KiB) ;
  - garde haute S1 (`__stack_top_guard_*`).
- Assertions : `boot_stack_top % 16 == 0` (l. 159) ; `__kernel_end <= 0x00400000` (l. 194). Tout le noyau tient dans les 4 premiers MiB.

### 3.3 Arguments de `kmain` — `kernel/core/kmain.c`

- Signature : `void kmain(uint32_t magic, uint32_t mbi_phys)` (l. 67), en convention cdecl i386 : arguments sur la pile, `[ESP+4]` = magic, `[ESP+8]` = MBI.
- À l'entrée, `ESP % 16 == 12`, vérifié par GDB (`tests/qemu/gdb_checks.sh`, test 1, `ESPMOD16=12`).
- Ordre d'initialisation : `log_init` → `gdt_init` (l. 89) → `idt_init` (l. 90) → `bootinfo_init(magic, mbi_phys)` (l. 94) → `kernel_layout_valid` → `mm_init` (l. 114) → `pic_init` (l. 119) → PIT → clavier → autotests (image de test) → `paging_seal_critical` → `paging_audit` → `idle_loop`.
- **IF = 1 seulement dans `idle_loop`**, par `cpu_sti()` (l. 60) après `cpu_idle`.
- **Avant `idt_init`, toute exception provoque un triple fault** [code, commentaire l. 79-80].

### 3.4 Structures Multiboot — `kernel/core/bootinfo.c`, `kernel/mm/mm.c`, `kernel/mm/pmm.c`

- `bootinfo_region_ok(addr, len)` (bootinfo.c l. 11) refuse :
  - `addr == 0` et `len == 0` ;
  - le débordement de `addr + len` au-delà de 2³² ;
  - tout chevauchement de `[__kernel_start, __kernel_end)`.
- `bootinfo_init` (l. 46) :
  - magic ≠ `0x2BADB002` → `SAMOS_EINVAL` ; dans ce cas `kmain` appelle `panic`, et ce refus est testé par GDB (test 2, `0xdeadbeef`) ;
  - copie `flags`, `mem_lower`, `mem_upper` ;
  - garde `mmap_addr`/`mmap_length` si la région est valide, sinon retire `MBI_FLAG_MMAP` ;
  - copie `cmdline` et `boot_loader_name` par `copy_untrusted_string`, copie bornée.
- `mm_init` (mm.c l. 26) : `memmap_parse(&g_memmap, mmap_addr, mmap_length)` **copie** la carte dans `g_memmap`. Après ce point, la carte d'origine n'est plus lue.
- `pmm_init` (pmm.c) **réserve** :
  - `[0, 1 MiB)` (l. 41) ;
  - l'image du noyau ;
  - la MBI (l. 53) et la carte (l. 56).
  - Elles ne sont donc jamais redistribuées.
- Toutes les adresses Multiboot sont des `uint32_t`, **inférieures à 4 GiB** [spec MB1].

### 3.5 GDT, IDT, exceptions

- `gdt.h` : 5 entrées. Sélecteurs `0x08` (code), `0x10` (données), `0x18` (TSS principale), `0x20` (TSS #DF).
- `struct tss` = 104 octets (TSS 32 bits) ; `g_tss_main.esp0 = boot_stack_top` (gdt.c l. 74).
- La TSS #DF a `eip = double_fault_task`, `esp` = sommet de S2, `cr3` = `cpu_read_cr3()` (l. 88), recopié après la pagination (l. 148).
- `idt.c` : 256 portes de 8 octets. 48 stubs, portes d'interruption 32 bits (`0x0E`).
- #DF passe par une **porte de tâche** (`idt_set_gate(EXC_DF, 0, GDT_TSS_DF_SEL, … IDT_TYPE_TASK)`, l. 55), et `lidt` est chargé à la l. 58.
- `isr_stubs.asm` : code d'erreur factice pour les vecteurs sans code, `isr_common` fait `pushad`, `iretd`.
- `struct interrupt_frame` (`interrupt.h` l. 49) : champs 32 bits, sans `ss:esp` puisque tout s'exécute en ring 0.
- `exceptions.c` : `isr_dispatch` (l. 131) ; une exception imbriquée appelle `panic("nested exception")` (l. 151), sauf la sonde de #PF.
- `double_fault_task` (l. 172) vérifie les sentinelles de S2, puis appelle `panic`.
- `panic_at` (`panic.c` l. 84) fait `cpu_cli`, affiche, fait `qemu_exit` dans l'image de test, puis `cpu_halt_forever` : comportement **fail-stop**.
- **Aucun de ces mécanismes n'existe en mode long :**
  - la commutation de tâche matérielle disparaît ;
  - les portes passent à 16 octets ;
  - `iretq` remplace `iretd` ;
  - le cadre empile toujours `SS:RSP` ;
  - la TSS 64 bits ne contient plus de registres [spec SDM vol. 3A ch. 6, 7, 8].

### 3.6 PMM, VMM et carte mémoire

- **Pagination :** 2 niveaux, sans PAE (`paging.h` : `PTE_FRAME 0xFFFFF000`). Il n'y a **pas de bit NX** en i386 sans PAE (`paging.h` l. 19).
- **Identité :** `PAGING_IDMAP_LIMIT 0x40000000` (1 GiB) ; `paging_init(idmap_top)` (paging.c l. 1096) active `CR0_PG | CR0_WP` (l. 1137), puis `seal_paging_structures`.
- **Pages jamais projetées** (`va_must_stay_unmapped`, l. 178) : la page nulle, la garde basse de S1, la garde de S2 et la garde haute de S1.
- **Écritures des PDE et PTE :** uniquement par `pt_gate_write`, une fenêtre CR0.WP contrôlée. `check_elf.sh` n'autorise les écritures de CR0 qu'aux endroits connus (règles « K0.7-P4c, P4e-1, P4e-2 »).
- **K1.0-N3 :**
  - `dyn_mapping_count` compte les projections réelles, au-delà de `idmap_top` ;
  - règle U2 : `pmm_unref` seulement si le cadre est ALLOCATED et si `refs ≥ D` ;
  - audits `ref_mismatch`, `mapped_type_mismatch`, `ref_surplus`.
- **Adresses :** tous les types physiques et virtuels du VMM sont des `uint32_t`.

### 3.7 Contraintes des bancs QEMU et GDB (M64-0)

- **Chargement :** QEMU `-kernel` charge un ELF32 Multiboot 1. Il **refuse** un ELF64 Multiboot 1 (« Cannot load x86-64 image, give a 32bit one ») et ne charge pas Multiboot 2 [exp K1.1, QEMU 8.2.2].
- **GDB sous `qemu-system-x86_64` :**
  - il faut imposer `set architecture i386:x86-64` avant `target remote` ;
  - `$esp`, `$eflags`, `$pc` et la mémoire sont exacts ;
  - `$eip`, le désassemblage 32 bits et les arguments C symboliques sont **faux** (rapport M64-0 §2).
- **Le mode mixte** (tremplin 32 bits puis code 64 bits dans la même session) **n'a jamais été testé** [hyp].
- **CPU par défaut :** `qemu64` sous `qemu-system-x86_64`. Mesure du 2026-11-20 [exp], `query-cpu-model-expansion` sous QEMU 8.2.2 :

| Modèle `-cpu` | lm | nx | pae | pse | pge | msr | pdpe1gb |
|---|---|---|---|---|---|---|---|
| `qemu32` | 0 | 0 | 1 | 1 | 1 | 1 | 0 |
| `qemu64` | 1 | 1 | 1 | 1 | 1 | 1 | 0 |
| `qemu64,-nx` | 1 | 0 | 1 | 1 | 1 | 1 | 0 |
| `qemu64,-lm` | 0 | 1 | 1 | 1 | 1 | 1 | 0 |
| `pentium3` | 0 | 0 | 1 | 1 | 1 | 1 | 0 |
| `core2duo` | 1 | 1 | 1 | 1 | 1 | 1 | 0 |

  Les refus « sans long mode » et « sans NX » sont donc testables sous QEMU sans matériel particulier. Un CPU **sans CPUID** n'a pas été trouvé parmi ces modèles [hyp : non testable simplement].

## 4. Contrat d'entrée (état au moment de `_start`)

### 4.1 Garanti par le protocole Multiboot 1 [spec, Multiboot 0.6.96 §3.2]

| Élément | Garantie |
|---|---|
| Mode CPU | mode protégé 32 bits : `CR0.PE = 1`, **`CR0.PG = 0`** ; les autres bits de CR0 sont indéfinis |
| EAX | `0x2BADB002` |
| EBX | adresse **physique** 32 bits de `struct multiboot_info` |
| CS | segment de code 32 bits en lecture et exécution, base 0, limite `0xFFFFFFFF` ; **valeur du sélecteur indéfinie** |
| DS, ES, FS, GS, SS | segments de données 32 bits en lecture et écriture, base 0, limite `0xFFFFFFFF` ; sélecteurs indéfinis |
| A20 | activée |
| EFLAGS | `VM = 0`, `IF = 0` ; le reste indéfini, **DF compris** |
| ESP | **indéfini** : le noyau doit créer sa propre pile |
| GDTR | **peut être invalide** : aucun registre de segment ne doit être rechargé avant une GDT propre |
| IDTR | indéfini : interruptions masquées jusqu'à une IDT propre |
| Image | segments ELF32 chargés à leur `p_paddr`, en-tête dans les 8 premiers KiB, aligné sur 4 |
| MBI et structures liées | placées **n'importe où** hors de l'image et des modules ; le noyau doit éviter de les écraser tant qu'il en a besoin |

**Non garanti par le protocole :**
- l'état de CR4, d'EFER (MSR `0xC0000080`) et des MSR en général ;
- l'état du PIC : des IRQ peuvent être en attente, masquées seulement par IF = 0 ;
- l'absence de NMI, qui ne se masque pas par `cli`.

### 4.2 À vérifier à l'exécution par le tremplin (aucune confiance accordée)

| # | Vérification | Raison | Comportement sur échec |
|---|---|---|---|
| E1 | `EAX == 0x2BADB002`, conservé jusqu'à `kmain` | loader non conforme | aujourd'hui `kmain` refuse (`bootinfo_init`). En 64 bits : **même refus en C 64 bits**, ou refus anticipé dans le tremplin [déc A-3] |
| E2 | `CR0.PG == 0` | déjà fait (entry.asm l. 182) | refus **avec diagnostic** (nouveau, §5.3) |
| E3 | CPUID disponible (bit `EFLAGS.ID`, bit 21, basculable) | sans CPUID, il n'y a pas de détection | refus diagnostiqué |
| E4 | `CPUID.80000000H:EAX ≥ 0x80000001` | pas de feuille étendue | refus |
| E5 | `CPUID.80000001H:EDX.LM` (bit 29) | mode long absent | refus « no long mode » |
| E6 | `CPUID.01H:EDX.PAE` (bit 6), `.MSR` (bit 5) | pour `CR4.PAE`, `RDMSR`/`WRMSR` | refus |
| E7 | `CPUID.80000001H:EDX.NX` (bit 20) | NX **requis** ou **facultatif** | [déc A-4] : refus, ou mode dégradé déclaré |
| E8 | MBI non nulle, sous 4 GiB, hors image, sans débordement | comme `bootinfo_region_ok` | refus en C (comme aujourd'hui) |
| E9 | MBI, carte et `cmdline` couvertes par l'identité temporaire **avant** toute lecture en 64 bits | sinon #PF en 64 bits, avant une IDT | soit copie en 32 bits avant la bascule, soit couverture vérifiée [déc A-5] |
| E10 | image, pile et tables temporaires dans des cadres non disponibles pour le chargeur, et hors de la MBI | même règle qu'aujourd'hui | contrôle de liaison et refus |

### 4.3 Adresse de chargement et contraintes de l'éditeur de liens

- Aujourd'hui : identité à 1 MiB, ELF32. Pour le noyau 64 bits, l'entrée `e_entry` lue par QEMU ou GRUB doit être une **adresse 32 bits de code 32 bits**.
- Format d'image, deux voies déjà repérées [exp K1.1 §4.2] :
  - **a.out kludge** (bit 16 de l'en-tête Multiboot, avec `header_addr`, `load_addr`, `load_end_addr`, `bss_end_addr`, `entry_addr`) sur un ELF64 ;
  - **conteneur ELF32** (`objcopy`).
  - C'est la décision [déc A-1], à prendre par expérience **avant** le code.
- Contraintes communes :
  - le code du tremplin est assemblé en `bits 32` dans une section dédiée (par exemple `.boot32`), adresse virtuelle = adresse physique, sous 4 GiB ;
  - le code 64 bits jusqu'à D-LAYOUT reste en identité basse (adresses canoniques puisque sous `2^47`), modèle de code `-mcmodel=kernel` ou `small` [déc A-6] ;
  - BSS et tables temporaires alignées sur 4 KiB, dans l'image (donc réservées par le PMM comme aujourd'hui) ;
  - assertions de liaison héritées : piles alignées, gardes contiguës, pas de W+X, `__kernel_end` borné.

### 4.4 Mémoire physique et pile à l'entrée

- **Pile :** aucune pile n'est fournie. La pile du tremplin doit être S1 (`boot_stack_top`, alignée sur 16), installée avant toute écriture, comme aujourd'hui.
- **Mémoire :** la seule mémoire sûre avant l'analyse de la carte est l'image elle-même. Le tremplin **ne doit rien écrire hors de l'image** : pas de tables à une adresse fixe hors liaison, pas de pile en mémoire basse.
- **Mémoire basse :** `[0, 1 MiB)` reste réservée ; le BDA et l'EBDA ne sont ni lus ni écrits par le tremplin.

### 5.2 Interruptions et exceptions pendant la transition

- **IRQ masquables :** IF = 0 de T0 jusqu'après l'installation de l'IDT 64 bits, dans le C (M64-4). Aucun `sti` dans le tremplin.
- **Exceptions de T0 à T10** : aucune IDT valide. L'IDT éventuelle du chargeur n'est pas fiable, et une IDT 32 bits **devient invalide** dès `EFER.LMA = 1`, car les portes sont relues comme portes de 16 octets [spec].
  - Toute exception dans cette fenêtre est donc un **triple fault**.
  - Le contrat l'accepte **seulement** si chaque étape faillible est précédée d'un contrôle qui refuse avec un diagnostic : T2 pour les MSR et les bits réservés, T3 pour les tables, et la vérification statique de la GDT.
- **NMI :** non masquable par `cli`.
  - Option 1 : accepter la fenêtre (quelques dizaines d'instructions) et la documenter.
  - Option 2 : masquer les NMI par le bit 7 du port `0x70` (CMOS, propre au PC) pendant la transition, puis les rétablir après l'IDT 64 bits.
  - Option 3 : IDT 64 bits minimale installée dès T11, avec une porte NMI qui fait un arrêt diagnostiqué.
  - [déc A-7]. Je recommande l'option 3, plus l'option 2 si elle est validée sous QEMU.
- **#DF :** aucune porte de tâche possible en mode long. Avant M64-4 (TSS64 et IST), un #DF est un triple fault.
- **SMI :** hors de portée ; transparente au noyau.

### 5.3 Fail-stop et diagnostic

- Chaque refus du tremplin écrit un **code court** sur le port série COM1 (`0x3F8`, en sondage) et sur `debugcon` (`0xE9`, image de test seulement, comme `CONFIG_QEMU_DEBUGCON`). Par exemple :
  - `M64: no cpuid`, `M64: no long mode`, `M64: no pae`, `M64: no msr`, `M64: no nx` (si NX est requis) ;
  - `M64: paging already on`, `M64: lma not set`.
- L'arrêt est `cli ; hlt` en boucle, comme `.halt` aujourd'hui.
- Dans l'image de test seulement, `isa-debug-exit` (`0xF4`) est appelé avec le statut 37 (« panique »), pour que les bancs jugent un refus **nommé** et non un délai dépassé ou un triple fault.
- Aucun refus silencieux, ce qui corrige le `.halt` silencieux actuel (entry.asm l. 184) pour le tremplin.
- Une bascule incomplète ne doit **jamais** continuer : chaque étape n'est atteinte que si la précédente a réussi.

### 5.4 Tables de pages temporaires (contrat, sans construction)

- **Rôle :** une identité minimale qui couvre :
  1. le code du tremplin et le code 64 bits ;
  2. la pile 64 bits ;
  3. les données lues avant la pagination définitive : la MBI, la carte et `cmdline`, sauf si elles sont copiées en 32 bits [déc A-5] ;
  4. les ports d'E/S, qui ne passent pas par la pagination.
- **Exigences :**
  - **page nulle absente** : la granularité doit être de 4 KiB sur les 2 premiers MiB. Une page de 2 MiB à l'adresse 0 rendrait NULL projetée ; elle est refusée dans la conception ;
  - **gardes S1 et S2 absentes**, sinon la pile 64 bits perd sa protection : granularité de 4 KiB sur `.stacks` ;
  - `.text` en lecture et exécution, `.rodata` RO, données et piles RW avec XD si `NXE` ; aucune page W+X ;
  - entrées non projetées à 0 (BSS) ; aucun bit réservé (`MAXPHYADDR` lu par `CPUID.80000008H` si des adresses > 4 GiB sont un jour projetées) ;
  - tables dans l'image (`.bss`, alignées sur 4 KiB), donc réservées par le PMM ;
  - **temporaires** : remplacées par les tables définitives scellées (M64-6/M64-7), puis retirées. Leur effacement est vérifié par un audit.
- **Option plus simple, à rejeter sauf décision :** identité de 1 GiB en pages de 2 MiB. Elle projette NULL et les gardes et ne permet pas les droits par page : c'est une perte d'invariants **pendant** la fenêtre temporaire [déc A-2].

### 6.1 Différences d'ABI : i386 actuel / System V AMD64 [spec ABI AMD64 §3.2]

| Point | i386 (cdecl, actuel) | System V AMD64 | Conséquence |
|---|---|---|---|
| Arguments entiers | pile (`[ESP+4]`, `[ESP+8]`) | `RDI`, `RSI`, `RDX`, `RCX`, `R8`, `R9` | `gdb_checks.sh` (ARG0/ARG1 sur la pile) doit lire les **registres** en 64 bits |
| Alignement à l'entrée | `ESP % 16 == 12` (vérifié) | `RSP % 16 == 8` | assertion et test GDB à réécrire, pas à reprendre |
| Registres préservés par l'appelé | EBX, ESI, EDI, EBP | RBX, RBP, R12 à R15 | stubs d'interruption et changements de contexte à réécrire |
| Zone rouge | aucune | 128 octets sous RSP | **interdite en noyau** (`-mno-red-zone`) : une interruption écraserait la zone |
| Retour | EAX (EDX:EAX) | RAX (RDX:RAX) | — |
| Taille de pointeur et de `long` | 32 bits | 64 bits (LP64) | **troncatures `(uint32_t)`** dans le VMM, le PMM et `bootinfo` : audit obligatoire |
| DF à l'appel | 0 (supposé) | 0 (exigé) | inchangé |
| Pile dans les interruptions | CPU : `EIP, CS, EFLAGS` (sans changement de privilège) | CPU : **toujours** `SS, RSP, RFLAGS, CS, RIP`, RSP aligné sur 16 | `struct interrupt_frame` à redéfinir |
| Traces de pile | chaîne EBP | chaîne RBP (`-fno-omit-frame-pointer` conservé) | — |

## 9. Stratégie de validation

### 9.1 Possible **avant** toute implémentation du tremplin

| Test | Type | Moyen |
|---|---|---|
| V1 : modèles de CPU avec et sans `lm`, `nx`, `pae` | environnement | QMP `query-cpu-model-expansion` (fait, §3.7) |
| V2 : chargement d'une image a.out kludge ou d'un conteneur ELF32 (A-1) | expérience jetable, hors dépôt | `qemu -kernel` sur une image minimale |
| V3 : GDB, architecture imposée, symboles ELF64 (H1) | expérience jetable | idem |
| V4 : NMI masquée par le port `0x70` (H3) | expérience jetable | `nmi` du moniteur QEMU |
| V5 : fonction pure de **décision CPUID** (entrée : valeurs EAX/EDX simulées ; sortie : accepté ou refus nommé) | test **hôte**, une fois la fonction autorisée | tableau de vecteurs, y compris les bits réservés et une feuille étendue absente |
| V6 : construction des tables temporaires en **fonction pure** (si elle est écrite en C hôte et testable) | test hôte | page 0 absente, gardes absentes, pas de W+X, alignements |
| V7 : troncatures LP64 (H6) | compilation hôte 64 bits des modules partagés | `-Wconversion` ciblé, tests hôte existants |

V5 et V6 demandent une autorisation d'écrire du code (de test). Ils ne font pas partie de ce document.

### 9.2 Nécessitant le futur tremplin (M64-2)

| # | Cas | Attendu, toujours un diagnostic **nommé** | Positif ou négatif |
|---|---|---|---|
| T-1 | démarrage `qemu64` à 128 MiB | message 64 bits, puis arrêt contrôlé | positif |
| T-2 | démarrage à 16 MiB, 512 MiB, 4 GiB | idem ; carte cohérente | positif |
| T-3 | `-cpu qemu32`, `-cpu qemu64,-lm` | `M64: no long mode`, statut 37, **sans triple fault** | négatif |
| T-4 | `-cpu qemu64,-nx` | refus `M64: no nx`, ou mode dégradé déclaré (A-4) | négatif |
| T-5 | magic falsifié par GDB avant la bascule | refus explicite (port de GDB test 2) | négatif |
| T-6 | MBI falsifiée (adresse 0, chevauchement de l'image, longueur débordante) | refus en C 64 bits, comme `bootinfo_region_ok` | négatif |
| T-7 | tables temporaires invalides, injectées dans l'image de test : bit réservé, PML4 non alignée, page 0 présente | refus par l'audit de construction **avant** T7 ; sinon #PF ou triple fault détecté et **compté comme FAIL** | négatif |
| T-8 | pile mal alignée, injectée | arrêt par l'assertion `RSP % 16` avant `call` | négatif |
| T-9 | registres de contrôle mal configurés, injectés : `PAE` absent, `LME` absent, `WP` absent | `M64: lma not set`, ou autotest de registres en échec | négatif |
| T-10 | transition incomplète (saut 64 bits retiré par mutation) | aucun message 64 bits, refus nommé ; un délai dépassé n'est jamais un succès | négatif |
| T-11 | GDB en mode mixte : arrêt dans le tremplin, puis dans le C 64 bits | valeurs attendues des deux côtés, ou **limitation documentée** et test marqué NOT TESTED, jamais un faux PASS | positif et négatif |
| T-12 | GDB en erreur (architecture inadaptée) en mode mixte | FAIL nommé (comme E5 de M64-0) | négatif |
| T-13 | référence i386 | 86/86 cas, GDB 8/8, sous les deux émulateurs ; images i386 identiques octet pour octet | régression |
| T-14 | mutations du tremplin : contrôle LM retiré, WP retiré, page 0 projetée, NXE retiré, alignement de pile retiré | chacune **détectée** par une assertion nommée | contre-tests |

**Règle :** un triple fault, un délai dépassé ou un arrêt sans message ne sont **jamais** comptés comme une détection (règle des bancs K0.7).

## 10. Risques

| Niveau | Risque | Mitigation |
|---|---|---|
| **HIGH** | exception ou NMI pendant la fenêtre sans IDT, donc triple fault non diagnostiqué | contrôles préalables (T2, T3, GDT statique) ; A-7 ; tests T-3, T-7, T-10 |

| **MEDIUM** | `EFER.NXE` oublié alors que XD est posé : #PF « réservé » | T6 conditionné à T2 ; test T-4 |
| **MEDIUM** | GDB incapable de suivre le mode mixte | H2 ; deux sessions ; NOT TESTED déclaré |
| **MEDIUM** | format d'image (A-1) qui casse les bancs (`-kernel`) ou les symboles | expérience V2/V3 avant le code |
| **MEDIUM** | MBI lue hors de l'identité en 64 bits | A-5 ; test T-6 |
| **MEDIUM** | dette de double construction i386/x86-64 | images i386 identiques octet pour octet à chaque jalon |
| **LOW** | `rdtsc` utilisé sans contrôle CPUID (i386 actuel) | documenté ; sans effet en 64 bits |
| **LOW** | CPU sans CPUID non simulable | NOT TESTED justifié |
| **LOW** | différences `qemu32`/`qemu64` masquant un comportement réel | D4 : pas de validation matérielle avant la revue de sûreté |

## 11. Critères d'acceptation de la future implémentation (M64-1/M64-2)

1. **Images i386 identiques** octet pour octet à la référence, dans un même répertoire, et 86/86 cas QEMU, GDB 8/8 sous les deux émulateurs.
2. Démarrage 64 bits reproductible à 128 MiB et 4 GiB, avec message 64 bits ; refus **nommés**, sans triple fault, sous `-cpu qemu32` et `-cpu qemu64,-lm`, et comportement A-4 sous `-cpu qemu64,-nx`.
3. Contrat de sortie S1 à S11 prouvé : autotests ou GDB, avec valeurs relevées dans le rapport.
4. Tables temporaires : page 0 et gardes **absentes**, prouvé par une sonde après l'IDT ou par un audit statique de la construction ; pas de W+X.
5. `check_elf` 64 bits : ELF64 ou conteneur conforme ; règles CR0 et INVLPG portées, **avec tests négatifs**.
6. Chaque mutation T-14 détectée par une assertion nommée.
7. Documentation : `README.md`, `Walkthrough.md`, `Details.md` (mode long, PAE, EFER, GDT64), rapport de jalon.
8. CI : deux variantes en `success` au SHA exact ; mutations exécutées et rapportées, en précisant si c'est en local ou sur GitHub.
9. Aucun invariant du §8 déclaré « préservé » sans la preuve de sa colonne.
