- **Nature :** document de conception **seulement**. Il ne contient aucun code de production, aucun tremplin, aucune table de pages, et ne modifie ni les tests ni la CI.
- **Base :** `main` = `origin/main` = `92b1880b34f572526bb70001ef78230c3b0eef16`. Branche : `claude/k1.1-m64-1-design`.
- **Référence i386 :** étiquette `ref/i386-k0.7`, objet `f671c13658c7cedff81c96ad4186013b54063256`, cible `7e43b786cc049e112b19e1ad786c15df6c4aeba9`.
- **Décisions déjà prises qui encadrent ce document :**
  - D1 = B : migration avant `kmalloc`, l'ordonnanceur et les processus ;
  - D2 = A : Multiboot 1 et tremplin 32 → 64 bits ; format d'image décidé sur expérience ;
  - D4 : émulation d'abord ;
  - D-REF, D-CI (`docs/review/K1.1-design-review.md` §10).
- **Décisions encore ouvertes :** D-LAYOUT, D-WP, D-N3, et les décisions nouvelles du §12.
- **Statut :** révision 3 (2026-11-20). Elle répond aux clarifications C1 (ordre de validation Multiboot) et C2 (frontières et permissions) demandées sur `c30ae80`, et enregistre les arbitrages Q1 à Q4. **En attente de validation.**
- **Portée :** ce document est la **conception commune de M64-1 et M64-2** (décision A-0). Il **n'autorise aucune implémentation**.
  - Le **prochain jalon d'implémentation possible est M64-1 seul** : construction double (`ARCH=x86_64` à côté de `ARCH=i386`), squelette qui se lie, `check_elf` ELF64, **sans tremplin**, sans table de pages, sans code exécuté en mode long.

  - Les contrats des §4 à §6 décrivent ce que M64-2 devra respecter. Ce ne sont pas des tâches de M64-1.

Conventions :
- **[code]** : fait lu dans le code actuel, avec fichier et ligne ;

Constats :
- **Aucune instruction `CPUID`** n'existe dans le noyau : grep `cpuid|EFER|PAE|NX` vide hors commentaire de `paging.h` [code].
- `rdtsc` est utilisé sans vérifier `CPUID.01H:EDX.TSC` : le noyau suppose un i586 ou plus. C'est sans conséquence en x86-64, où TSC est toujours présent [spec], mais c'est une hypothèse implicite.
- Les refus précoces (`.halt`) sont **silencieux** : aucun message avant `kmain`.

### 3.2 Script de liaison — `kernel/arch/i386/linker.ld`

- `OUTPUT_FORMAT("elf32-i386")` (l. 25), `OUTPUT_ARCH(i386)`, `KERNEL_LOAD_ADDR = 0x00100000` (l. 29) : identité, adresse virtuelle = adresse physique.
- Trois `PHDRS` : `text` R-X, `rodata` R--, `data` RW-. `check_elf.sh` refuse tout segment W+X et exige vaddr = paddr ≥ 1 MiB.
- `.bss` commence par les pages critiques, chacune alignée et d'exactement une page :
  - `__kcpu_*` : GDT et 2 TSS, laissées RW ;
  - `__kro_idt_*` : IDT ;
  - `__kro_handlers_*` : tables de gestionnaires ;
  - `__kro_vmm_*` : `g_pd`, `g_idmap_top`.
- `.stacks` (NOLOAD, ni chargée ni remise à zéro), de bas en haut :
  - garde S2 (`__df_guard_*`, 4 KiB) ;
  - S2 (`df_stack_area`, 4 KiB) ;
  - garde basse S1 (`__stack_guard_*`) ;
  - S1 (`boot_stack_bottom` … `boot_stack_top`, 16 KiB) ;
  - garde haute S1 (`__stack_top_guard_*`).
- Assertions : `boot_stack_top % 16 == 0` (l. 159) ; `__kernel_end <= 0x00400000` (l. 194). Tout le noyau tient dans les 4 premiers MiB.

### 3.3 Arguments de `kmain` — `kernel/core/kmain.c`

- Signature : `void kmain(uint32_t magic, uint32_t mbi_phys)` (l. 67), en convention cdecl i386 : arguments sur la pile, `[ESP+4]` = magic, `[ESP+8]` = MBI.
- À l'entrée, `ESP % 16 == 12`, vérifié par GDB (`tests/qemu/gdb_checks.sh`, test 1, `ESPMOD16=12`).
- Ordre d'initialisation : `log_init` → `gdt_init` (l. 89) → `idt_init` (l. 90) → `bootinfo_init(magic, mbi_phys)` (l. 94) → `kernel_layout_valid` → `mm_init` (l. 114) → `pic_init` (l. 119) → PIT → clavier → autotests (image de test) → `paging_seal_critical` → `paging_audit` → `idle_loop`.
- **IF = 1 seulement dans `idle_loop`**, par `cpu_sti()` (l. 60) après `cpu_idle`.
- **Avant `idt_init`, toute exception provoque un triple fault** [code, commentaire l. 79-80].

### 3.4 Structures Multiboot — `kernel/core/bootinfo.c`, `kernel/mm/mm.c`, `kernel/mm/pmm.c`

- `bootinfo_region_ok(addr, len)` (bootinfo.c l. 11) refuse :
  - `addr == 0` et `len == 0` ;
  - le débordement de `addr + len` au-delà de 2³² ;
  - tout chevauchement de `[__kernel_start, __kernel_end)`.
- `bootinfo_init` (l. 46) :
  - magic ≠ `0x2BADB002` → `SAMOS_EINVAL` ; dans ce cas `kmain` appelle `panic`, et ce refus est testé par GDB (test 2, `0xdeadbeef`) ;
  - copie `flags`, `mem_lower`, `mem_upper` ;
  - garde `mmap_addr`/`mmap_length` si la région est valide, sinon retire `MBI_FLAG_MMAP` ;
  - copie `cmdline` et `boot_loader_name` par `copy_untrusted_string`, copie bornée.
- `mm_init` (mm.c l. 26) : `memmap_parse(&g_memmap, mmap_addr, mmap_length)` **copie** la carte dans `g_memmap`. Après ce point, la carte d'origine n'est plus lue.
- `pmm_init` (pmm.c) **réserve** :
  - `[0, 1 MiB)` (l. 41) ;
  - l'image du noyau ;
  - la MBI (l. 53) et la carte (l. 56).
  - Elles ne sont donc jamais redistribuées.
- Toutes les adresses Multiboot sont des `uint32_t`, **inférieures à 4 GiB** [spec MB1].

### 3.5 GDT, IDT, exceptions

- `gdt.h` : 5 entrées. Sélecteurs `0x08` (code), `0x10` (données), `0x18` (TSS principale), `0x20` (TSS #DF).
- `struct tss` = 104 octets (TSS 32 bits) ; `g_tss_main.esp0 = boot_stack_top` (gdt.c l. 74).
- La TSS #DF a `eip = double_fault_task`, `esp` = sommet de S2, `cr3` = `cpu_read_cr3()` (l. 88), recopié après la pagination (l. 148).
- `idt.c` : 256 portes de 8 octets. 48 stubs, portes d'interruption 32 bits (`0x0E`).
- #DF passe par une **porte de tâche** (`idt_set_gate(EXC_DF, 0, GDT_TSS_DF_SEL, … IDT_TYPE_TASK)`, l. 55), et `lidt` est chargé à la l. 58.
- `isr_stubs.asm` : code d'erreur factice pour les vecteurs sans code, `isr_common` fait `pushad`, `iretd`.
- `struct interrupt_frame` (`interrupt.h` l. 49) : champs 32 bits, sans `ss:esp` puisque tout s'exécute en ring 0.
- `exceptions.c` : `isr_dispatch` (l. 131) ; une exception imbriquée appelle `panic("nested exception")` (l. 151), sauf la sonde de #PF.
- `double_fault_task` (l. 172) vérifie les sentinelles de S2, puis appelle `panic`.
- `panic_at` (`panic.c` l. 84) fait `cpu_cli`, affiche, fait `qemu_exit` dans l'image de test, puis `cpu_halt_forever` : comportement **fail-stop**.
- **Aucun de ces mécanismes n'existe en mode long :**
  - la commutation de tâche matérielle disparaît ;
  - les portes passent à 16 octets ;
  - `iretq` remplace `iretd` ;
  - le cadre empile toujours `SS:RSP` ;
  - la TSS 64 bits ne contient plus de registres [spec SDM vol. 3A ch. 6, 7, 8].

### 3.6 PMM, VMM et carte mémoire

- **Pagination :** 2 niveaux, sans PAE (`paging.h` : `PTE_FRAME 0xFFFFF000`). Il n'y a **pas de bit NX** en i386 sans PAE (`paging.h` l. 19).
- **Identité :** `PAGING_IDMAP_LIMIT 0x40000000` (1 GiB) ; `paging_init(idmap_top)` (paging.c l. 1096) active `CR0_PG | CR0_WP` (l. 1137), puis `seal_paging_structures`.
- **Pages jamais projetées** (`va_must_stay_unmapped`, l. 178) : la page nulle, la garde basse de S1, la garde de S2 et la garde haute de S1.
- **Écritures des PDE et PTE :** uniquement par `pt_gate_write`, une fenêtre CR0.WP contrôlée. `check_elf.sh` n'autorise les écritures de CR0 qu'aux endroits connus (règles « K0.7-P4c, P4e-1, P4e-2 »).
- **K1.0-N3 :**
  - `dyn_mapping_count` compte les projections réelles, au-delà de `idmap_top` ;
  - règle U2 : `pmm_unref` seulement si le cadre est ALLOCATED et si `refs ≥ D` ;
  - audits `ref_mismatch`, `mapped_type_mismatch`, `ref_surplus`.
- **Adresses :** tous les types physiques et virtuels du VMM sont des `uint32_t`.

### 3.7 Contraintes des bancs QEMU et GDB (M64-0)

- **Chargement :** QEMU `-kernel` charge un ELF32 Multiboot 1. Il **refuse** un ELF64 Multiboot 1 (« Cannot load x86-64 image, give a 32bit one ») et ne charge pas Multiboot 2 [exp K1.1, QEMU 8.2.2].
- **GDB sous `qemu-system-x86_64` :**
  - il faut imposer `set architecture i386:x86-64` avant `target remote` ;
  - `$esp`, `$eflags`, `$pc` et la mémoire sont exacts ;
  - `$eip`, le désassemblage 32 bits et les arguments C symboliques sont **faux** (rapport M64-0 §2).
- **Le mode mixte** (tremplin 32 bits puis code 64 bits dans la même session) **n'a jamais été testé** [hyp].
- **CPU par défaut :** `qemu64` sous `qemu-system-x86_64`. Mesure du 2026-11-20 [exp], `query-cpu-model-expansion` sous QEMU 8.2.2 :

| Modèle `-cpu` | lm | nx | pae | pse | pge | msr | pdpe1gb |
|---|---|---|---|---|---|---|---|
| `qemu32` | 0 | 0 | 1 | 1 | 1 | 1 | 0 |
| `qemu64` | 1 | 1 | 1 | 1 | 1 | 1 | 0 |
| `qemu64,-nx` | 1 | 0 | 1 | 1 | 1 | 1 | 0 |
| `qemu64,-lm` | 0 | 1 | 1 | 1 | 1 | 1 | 0 |
| `pentium3` | 0 | 0 | 1 | 1 | 1 | 1 | 0 |
| `core2duo` | 1 | 1 | 1 | 1 | 1 | 1 | 0 |

  Les refus « sans long mode » et « sans NX » sont donc testables sous QEMU sans matériel particulier. Un CPU **sans CPUID** n'a pas été trouvé parmi ces modèles [hyp : non testable simplement].

## 4. Contrat d'entrée (état au moment de `_start`)

### 4.1 Garanti par le protocole Multiboot 1 [spec, Multiboot 0.6.96 §3.2]

| Élément | Garantie |
|---|---|
| Mode CPU | mode protégé 32 bits : `CR0.PE = 1`, **`CR0.PG = 0`** ; les autres bits de CR0 sont indéfinis |
| EAX | `0x2BADB002` |
| EBX | adresse **physique** 32 bits de `struct multiboot_info` |
| CS | segment de code 32 bits en lecture et exécution, base 0, limite `0xFFFFFFFF` ; **valeur du sélecteur indéfinie** |
| DS, ES, FS, GS, SS | segments de données 32 bits en lecture et écriture, base 0, limite `0xFFFFFFFF` ; sélecteurs indéfinis |
| A20 | activée |
| EFLAGS | `VM = 0`, `IF = 0` ; le reste indéfini, **DF compris** |
| ESP | **indéfini** : le noyau doit créer sa propre pile |
| GDTR | **peut être invalide** : aucun registre de segment ne doit être rechargé avant une GDT propre |
| IDTR | indéfini : interruptions masquées jusqu'à une IDT propre |
| Image | segments ELF32 chargés à leur `p_paddr`, en-tête dans les 8 premiers KiB, aligné sur 4 |
| MBI et structures liées | placées **n'importe où** hors de l'image et des modules ; le noyau doit éviter de les écraser tant qu'il en a besoin |

**Non garanti par le protocole :**
- l'état de CR4, d'EFER (MSR `0xC0000080`) et des MSR en général ;
- l'état du PIC : des IRQ peuvent être en attente, masquées seulement par IF = 0 ;
- l'absence de NMI, qui ne se masque pas par `cli`.

### 4.2 À vérifier à l'exécution par le tremplin (aucune confiance accordée)

| # | Vérification | Raison | Comportement sur échec |
|---|---|---|---|
| E1 | `EAX == 0x2BADB002`, conservé jusqu'au C 64 bits | loader non conforme | **refus en C 64 bits (A-3)**, avant tout déréférencement de la MBI. Le tremplin conserve la valeur sans la juger et ne lit pas la MBI |
| E2 | `CR0.PG == 0` | déjà fait (entry.asm l. 182) | refus **avec diagnostic** (nouveau, §5.3) |
| E3 | CPUID disponible (bit `EFLAGS.ID`, bit 21, basculable) | sans CPUID, il n'y a pas de détection | refus diagnostiqué |
| E4 | `CPUID.80000000H:EAX ≥ 0x80000001` | pas de feuille étendue | refus |
| E5 | `CPUID.80000001H:EDX.LM` (bit 29) | mode long absent | refus « no long mode » |
| E6 | `CPUID.01H:EDX.PAE` (bit 6), `.MSR` (bit 5) | pour `CR4.PAE`, `RDMSR`/`WRMSR` | refus |
| E7 | `CPUID.80000001H:EDX.NX` (bit 20) | NX **requis** pour la première cible (A-4) | refus `M64: no nx` |
| E8 | MBI : adresse non nulle, sans débordement, hors image, et les **88 octets lus** (`sizeof(struct multiboot_info)`) entièrement dans l'identité vérifiée | comme `bootinfo_region_ok`, plus la couverture | refus en C, **avant toute lecture** de la MBI (§4.5, étape V1) |
| E9 | chaque pointeur de la MBI réellement utilisé (carte, `cmdline`, nom du chargeur) : plage **entière** dans l'identité vérifiée **avant** sa lecture (A-5) | sinon #PF (diagnostiqué par l'IDT minimale, mais refus attendu avant) | §4.5, étapes V3 et V4 : refus nommé, ou structure ignorée, **sans lecture** |
| E10 | image, pile et tables temporaires dans des cadres non disponibles pour le chargeur, et hors de la MBI | même règle qu'aujourd'hui | contrôle de liaison et refus |

### 4.3 Adresse de chargement et contraintes de l'éditeur de liens

- Aujourd'hui : identité à 1 MiB, ELF32. Pour le noyau 64 bits, l'entrée `e_entry` lue par QEMU ou GRUB doit être une **adresse 32 bits de code 32 bits**.
- Format d'image, deux voies déjà repérées [exp K1.1 §4.2] :
  - **a.out kludge** (bit 16 de l'en-tête Multiboot, avec `header_addr`, `load_addr`, `load_end_addr`, `bss_end_addr`, `entry_addr`) sur un ELF64 ;
  - **conteneur ELF32** (`objcopy`).
  - C'est la décision A-1, **différée** : expériences jetables V2 et V3 obligatoires avant tout choix, et aucun format revendiqué en M64-1.
- Contraintes communes :
  - le code du tremplin est assemblé en `bits 32` dans une section dédiée (par exemple `.boot32`), adresse virtuelle = adresse physique, sous 4 GiB ;
  - le code 64 bits jusqu'à D-LAYOUT reste en identité basse (adresses canoniques puisque sous `2^47`), modèle de code `-mcmodel=kernel` ou `small` (A-6, **différée** jusqu'à D-LAYOUT) ;
  - BSS et tables temporaires alignées sur 4 KiB, dans l'image (donc réservées par le PMM comme aujourd'hui) ;
  - assertions de liaison héritées : piles alignées, gardes contiguës, pas de W+X, `__kernel_end` borné.

### 4.4 Mémoire physique et pile à l'entrée

- **Pile :** aucune pile n'est fournie. La pile du tremplin doit être S1 (`boot_stack_top`, alignée sur 16), installée avant toute écriture, comme aujourd'hui.
- **Mémoire :** la seule mémoire sûre avant l'analyse de la carte est l'image elle-même. Le tremplin **ne doit rien écrire hors de l'image** : pas de tables à une adresse fixe hors liaison, pas de pile en mémoire basse.
- **Mémoire basse :** `[0, 1 MiB)` reste réservée ; le BDA et l'EBDA ne sont ni lus ni écrits par le tremplin.

### 4.5 Ordre de validation des structures Multiboot (C 64 bits ; A-3, A-5 ; C1)

**Ce que Multiboot 1 garantit et ne garantit pas [spec §3.2, §3.3]**
- **Garanti :** EBX contient une adresse **physique 32 bits**. La MBI et les structures qu'elle désigne (carte, chaînes) ne recouvrent ni l'image ni les modules.
- **Non garanti :** leur **emplacement**. La spécification les autorise « n'importe où » en mémoire physique, sans borne ni alignement ; elle n'impose pas non plus que la `cmdline` soit courte.
- **Adresses observées sous QEMU 8.2.2** (`0x9000`, `0x9500`, `0x198000`, `0x198011`, §7.1) : ce sont des **observations d'une implémentation**, pas des garanties. GRUB, un autre QEMU ou une autre taille d'image peuvent placer ces structures ailleurs, y compris au-delà de 4 MiB.

**Limite de 4 MiB : restriction de compatibilité du prototype**
- C'est **notre** choix de couverture pour l'identité temporaire (§5.4, Q3). **Ce n'est pas une exigence de Multiboot.**
- **Conséquence :** un chargeur conforme qui place une structure au-delà de 4 MiB, ou dans une zone non projetée, sera **refusé** par SAMOS (refus nommé), alors que la spécification l'autorise. C'est une **perte de compatibilité volontaire**, documentée.
- **Levée prévue :** avec les tables définitives (M64-6, D-LAYOUT), ou par une identité temporaire élargie sur décision.

**Ordre imposé (aucune étape ne lit une donnée non validée par les précédentes)**

| Étape | Action | Lit la MBI ? | Contrôle | Échec |
|---|---|---|---|---|
| V0 | magic (valeur de registre transmise en `RDI`) | **non** | `magic == 0x2BADB002` | refus « invalid multiboot magic », sans lecture (A-3, T-16) |
| V1 | adresse de la MBI (valeur en `RSI`) : **couverture minimale** | **non** | `mbi != 0` ; `mbi + 88` sans débordement ; `[mbi, mbi + 88)` hors image ; `[mbi, mbi + 88)` **entièrement** dans les zones projetées en lecture (§5.4.3), page 0 exclue | refus « invalid multiboot info address », sans lecture (E8, T-18) |
| V2 | lecture des champs : `flags`, puis seulement les champs dont le bit est posé (`mem_*`, `mmap_*`, `cmdline`, `boot_loader_name`) | **oui**, dans `[mbi, mbi + 88)` validé | — | — |
| V3 | **validation de chaque pointeur** et de sa plage, avant toute lecture de la cible | non (sur la cible) | carte : `mmap_addr != 0`, `mmap_length > 0`, pas de débordement, hors image, `[mmap_addr, mmap_addr + mmap_length)` couvert. Chaîne : `addr != 0`, et `[addr, addr + n)` couvert, où `n = min(cap, fin de la zone couverte − addr)`, avec `n ≥ 1` | carte invalide : drapeau `MMAP` retiré (comme aujourd'hui), puis repli sur `mem_*`. | V5 | les données copiées (`g_bootinfo`, `g_memmap`) sont la seule source utilisée ensuite | non | — | — |

**Écart avec le code actuel (constat, aucune modification ici)**
- `bootinfo_init` respecte déjà V0, puis V1 (sans la couverture), puis V2.
- En revanche, `copy_untrusted_string` (bootinfo.c l. 36) ne vérifie que **le premier octet** (`bootinfo_region_ok(cmdline, 1)`), puis lit jusqu'à `cap` octets.
- Avec l'identité de 1 GiB de l'i386 actuel, cette lecture reste dans la mémoire projetée. Avec l'identité de 4 MiB du prototype 64 bits, une chaîne proche de la fin de la zone couverte provoquerait un #PF.
- **V3 et V4 sont donc des exigences nouvelles pour le code 64 bits.** Leur report éventuel dans le code i386 demanderait une autorisation distincte.

### 5.2 Fenêtre sans IDT : exceptions évitables, NMI, risques résiduels

**Principe : un triple fault n'est jamais un fail-stop diagnostiqué.** C'est une réinitialisation du processeur. Sous QEMU avec `-no-reboot`, elle se traduit par l'arrêt de la machine et la ligne `Triple fault` du journal `-d cpu_reset`. Les bancs la comptent comme un **FAIL**, jamais comme une détection (règle K0.7). Un fail-stop diagnostiqué exige qu'un code SAMOS ait **écrit un message nommé** avant l'arrêt.

**Fenêtres :**

| Fenêtre | Mécanisme d'exception disponible | Conséquence d'une exception |
|---|---|---|
| W1 : `_start` → T7 (32 bits, sans pagination) | IDT du chargeur, **non fiable** (MB1 : IDTR indéfini) | triple fault, ou exécution d'un gestionnaire inconnu : **non diagnostiqué** |
| W2 : T7 → T11b (mode compatibilité puis 64 bits, avant l'IDT minimale) | aucun. Une IDT 32 bits serait relue comme portes de 16 octets dès `EFER.LMA = 1` [spec] | triple fault **non diagnostiqué** |
| W3 : après T11b | IDT minimale 64 bits | arrêt **diagnostiqué** (vecteur, RIP, code d'erreur) |
| W4 : après M64-4 | IDT, TSS64, IST | gestion complète, #DF sur IST |

**a) Exceptions évitables (W1, W2) : prévenues par construction, jamais « gérées »**

| Source possible | Prévention | Où |
|---|---|---|
| `CPUID` absent → #UD | test du bit `EFLAGS.ID` avant `CPUID` | T2 |
| `RDMSR`/`WRMSR` sur un CPU sans MSR, bit réservé d'EFER → #GP | T2 (MSR, LM, NX) avant T6 | T2, T6 |
| tables invalides au moment de `CR0.PG` → #PF au chargement de l'instruction suivante | audit statique T3b avant T5 et T7 | T3b |
| descripteur de code 64 bits faux → #GP au saut lointain | audit des descripteurs (T9) | T9 |
| écriture du bit Accessed dans une GDT en page RO | Accessed pré-positionné, ou GDT en page RW | T9 |
| pile non projetée ou sur une garde → #PF au premier `push` | pile S1 couverte, gardes absentes : vérifié par T3b | T3b, T11 |
| accès mémoire hors de l'identité temporaire | aucun accès mémoire du tremplin hors de l'image ; la MBI n'est pas lue avant le C (A-3, A-5) | T0 à T12 |

Chaque prévention est un **contrôle exécuté avant** l'opération risquée, avec un refus diagnostiqué en code 32 bits (ports d'E/S). Une exception qui survient malgré tout dans W1 ou W2 est un **défaut d'implémentation**. Elle n'est pas un comportement prévu, et le test qui la provoque échoue.

**b) NMI : non garantissables**

- Une NMI ne se masque pas par `cli`.
- Dans W1 et W2, une NMI conduit au triple fault ou à un gestionnaire du chargeur. **Aucune prévention n'est garantie.**
- Le masquage par le port `0x70` (bit 7) **n'est pas retenu** sans expérience (A-7, H3).
- La seule mesure retenue est de **réduire W2** : IDT minimale dès T11b, avec une porte NMI qui arrête avec un diagnostic.
- Dans W1, la fenêtre va de quelques centaines à quelques milliers d'instructions, dont la construction des tables. Elle n'est pas couverte.

**c) Risques résiduels (acceptés seulement par décision, jamais présentés comme diagnostiqués)**

| Risque | Fenêtre | Statut |
|---|---|---|
| NMI ou #MC dans W1 ou W2 | W1, W2 | **non couvert** : triple fault possible |
| SMI | toutes | transparente au noyau ; hors de portée |
| #DF dans W3 (avant IST) : exception pendant la livraison d'une exception, ou pile corrompue | W3 | sans IST, le #DF utilise la **pile courante**. Si elle est la cause, triple fault **non diagnostiqué**. Couvert seulement par M64-4 |
| exception dans le gestionnaire minimal lui-même | W3 | triple fault possible ; gestionnaire minimal sans appel C ni accès hors de l'image |

Tests (§9.2) : chaque prévention de a) a un **test négatif** qui provoque la condition (T-3, T-4, T-7, T-9). Le résultat attendu est le **refus nommé**. Un triple fault observé dans ces tests est un FAIL.

### 5.3 Fail-stop et diagnostic

Un fail-stop n'est **diagnostiqué** que s'il produit un message nommé. C'est le cas :
- dans W1 et W2, pour un refus du tremplin **avant** l'opération risquée ;
- dans W3, par l'IDT minimale ;
- ensuite, par `panic`.

- **Messages :** un code court sur COM1 (`0x3F8`, en sondage) et sur `debugcon` (`0xE9`, image de test seulement), par exemple :
  - `M64: no cpuid`, `M64: no long mode`, `M64: no pae`, `M64: no msr`, `M64: no nx` ;
  - `M64: paging already on`, `M64: bad page tables (entry N)`, `M64: lma not set`, `M64: bad stack alignment` ;
  - et, depuis l'IDT minimale, `M64: exception V at RIP R err E`.
- **Arrêt :** `cli ; hlt` en boucle. Dans l'image de test, `isa-debug-exit` (`0xF4`) avec le statut 37, pour que les bancs jugent un refus **nommé**.
- **Pas de refus silencieux :** le refus silencieux actuel (`.halt`, entry.asm l. 184 et 213) n'est **pas** reproduit dans le tremplin.
- **Aucune poursuite après échec :** chaque étape n'est atteinte que si la précédente a réussi.

### 5.4 Tables de pages temporaires (contrat, sans construction)

#### 5.4.1 Rôle et durée de vie

- **Rôle :** une identité minimale qui permet d'exécuter le code de transition et le début du C 64 bits, **jusqu'à leur remplacement** par les tables définitives scellées (M64-6/M64-7, D-LAYOUT).
- **Retrait :** après le remplacement, les pages des tables temporaires sont libérées ou réutilisées seulement après un INVLPG ou un rechargement de CR3, puis un audit prouvant qu'aucune entrée de CR3 ne les désigne plus.

#### 5.4.2 Construction (pagination désactivée, T3)

- **Mode d'accès :** pagination désactivée, donc adresse linéaire = adresse physique. Le tremplin écrit les entrées **directement**, sans fenêtre WP : CR0.PG = 0, donc WP sans effet.
- **Emplacement :** pages alignées sur 4 KiB, dans la `.bss` de l'image (remise à zéro en T1), donc :
  - hors de la MBI ;
  - réservées par le PMM comme l'image ;
  - exemptes de toute dépendance à une adresse fixe.
- **Hiérarchie minimale** pour un noyau sous 4 MiB (linker.ld l. 194) :
  - PML4[0] → PDPT ;
  - PDPT[0] → PD ;
  - PD[0] → PT0 (pour [0, 2 MiB)) et PD[1] → PT1 (pour [2, 4 MiB)) ;
  - soit **5 pages** de tables, toutes en pages de 4 KiB (A-2 sur toute la zone utile ; aucune page de 2 MiB).
- **Entrées non feuilles** (PML4E, PDPTE, PDE) : `P | RW`, **sans XD** et sans US. Les droits effectifs sont l'intersection des niveaux : c'est la PTE qui décide [spec SDM §4.6].
- **Aucun bit G** (CR4.PGE non posé), **aucun bit réservé**. Toutes les adresses sont < 4 MiB, donc < `MAXPHYADDR` dans tous les cas.

#### 5.4.3 Droits des feuilles (PTE), en vigueur à partir de T7

| Plage | Contenu | PTE | Justification |

Prototype seulement. **Projeter n'implique pas que la zone soit de la RAM utilisable** : elle contient la zone réservée basse, l'EBDA, la mémoire vidéo et les ROM. | [`0xB8000`, `0xB9000`) | tampon VGA texte | `P \| RW \| XD` | console VGA (M64-3) |

| `.rodata` (y compris la GDT64 du tremplin, Accessed pré-positionné) | constantes | `P`, RO, XD | — |
| `.data`, `.bss` hors tables temporaires | données | `P \| RW \| XD` | — |

- **Avant T7** (pagination désactivée), ces droits n'ont **aucun effet** : tout est accessible en lecture, écriture et exécution. Le tremplin ne doit donc compter sur aucune protection avant T7.
- **Après T7**, avec CR0.WP = 1, ils s'appliquent aussi au ring 0. Avec EFER.NXE = 1 (T6), XD est respecté.

#### 5.4.4 Preuves exigées

| Preuve | Nature | Quand | Ce qu'elle établit |

#### 5.4.5 Frontières de régions et compatibilité des permissions (C2)

**Principe :**
- Une PTE porte **un seul** jeu de droits pour 4 KiB. Une page ne peut donc contenir que des octets d'une **même classe** de permissions.
- Deux régions de classes différentes qui partagent une page imposent soit de les affaiblir toutes deux (W+X, ou RW sur du code), soit de rendre l'une inaccessible. Le contrat l'**interdit**.

**Classes et frontières exigées :**

| Région (symboles) | Classe | Frontière de début | Frontière de fin | Ce qui l'impose |
|---|---|---|---|---|
| `.text` (`__text_start` … `__text_end`, y compris `.multiboot` et le tremplin) | R-X | page (4 KiB) | page : la région suivante commence à `ALIGN(PAGE_SIZE)` | **existant i386** : `.rodata ALIGN(PAGE_SIZE)` (linker.ld l. 55) ; `check_elf.sh` l. 89 (début de section aligné), l. 99 (ordre), l. 76 (aucun PT_LOAD W+X) |
| `.rodata` (y compris la GDT64, Accessed pré-positionné) | R-- XD | page | page (`.data ALIGN(PAGE_SIZE)`, l. 62) | idem |
| `.data` et `.bss` ordinaires | RW- XD | page (l. 62, l. 72) | page | idem ; `.data` et `.bss` partagent la même classe : leur contact est permis |
| **tables temporaires** (`.bss.m64_pt`, nouveau) | R-- XD après T7 | **page**, en tête ou isolée dans `.bss` | **page** : exactement 5 pages, sans autre objet | **nouveau** (§5.4.5, règles R1 à R3) |
| `.stacks` (gardes et piles) | gardes : non présentes ; piles : RW- XD | page (l. 122) | page (l. 141) | **existant** : assertions de linker.ld (gardes de 4 KiB, contiguës, alignées), `check_elf.sh` l. 113-140 |
| [`__kernel_end`, 4 MiB) | R-- XD | page (`__kernel_end` aligné, l. 141) | 4 MiB | `ASSERT(__kernel_end <= 4 MiB)` (l. 194) |

**Règles de liaison nouvelles (pour la liaison 64 bits de M64-1/M64-2 ; aucune n'est écrite ici)**
- **R1** : `ASSERT((__m64_pt_start % PAGE_SIZE) == 0)` et `ASSERT(__m64_pt_end - __m64_pt_start == 5 * PAGE_SIZE)`.
- **R2** : la sortie `.bss.m64_pt` ne contient **que** les cinq tables. `check_elf` vérifie qu'aucun autre symbole ne tombe dans [`__m64_pt_start`, `__m64_pt_end`). C'est la même technique que la règle P4b actuelle (`check_elf.sh` l. 153-166 : une page, des symboles connus).
- **R3** : les pages voisines des tables, avant et après, sont d'une autre classe autorisée (RW- XD). Elles **ne partagent aucune page** avec les tables (R1 suffit si les deux bornes sont alignées).
- **R4** : début de **chaque** section de sortie aligné sur 4 KiB, et ordre `.text < .rodata < .data < .bss < .stacks`, comme `check_elf.sh` l. 89 et 99, reportés en ELF64.
- **R5** : aucun segment PT_LOAD W+X, comme `check_elf.sh` l. 76, reporté en ELF64. Cela ne suffit pas seul, puisqu'un segment peut couvrir plusieurs classes : R4 et P1 le complètent.

**Vérification à l'exécution (P1 étendu)**
- L'audit T3b calcule, **pour chaque page** de [0, 4 MiB), la classe attendue à partir des symboles de liaison.
- Il **refuse**, avec un message nommé, toute page qui recevrait deux classes incompatibles, par exemple si `__text_end` et `__rodata_start` ne sont pas séparés par une frontière de page. Cela protège contre un script de liaison modifié qui passerait les assertions par erreur.

**Avant l'activation de la pagination**
- **Aucune** de ces permissions n'a d'effet avant T7. Elles ne sont pas évaluées avant que CR0.PG = 1, et XD ne l'est pas avant EFER.NXE = 1.
- Le contrat ne déclare donc **aucune protection effective** pendant W1 (§5.2). Les frontières garantissent seulement que les droits annoncés **pourront** être appliqués, et P1 vérifie les entrées avant T5.

**Contre-tests (§9.2 : T-20, T-21, T-22)**
- frontière mal alignée : `ALIGN(PAGE_SIZE)` de `.rodata` retiré ;
- objet RW placé dans `.bss.m64_pt` ;
- chevauchement de classes dans une même page.
- Chacun doit être refusé **à la liaison** (assertion), **par `check_elf`** (règle nommée), **ou par P1** (message nommé), et jamais accepté en silence.

**Une identité de 1 GiB en pages de 2 MiB est rejetée** (A-2). Elle projetterait NULL et les gardes et ne permettrait pas de droits par page.

### 6.1 Différences d'ABI : i386 actuel / System V AMD64 [spec ABI AMD64 §3.2]

| Point | i386 (cdecl, actuel) | System V AMD64 | Conséquence |
|---|---|---|---|
| Arguments entiers | pile (`[ESP+4]`, `[ESP+8]`) | `RDI`, `RSI`, `RDX`, `RCX`, `R8`, `R9` | `gdb_checks.sh` (ARG0/ARG1 sur la pile) doit lire les **registres** en 64 bits |
| Alignement | avant `call` : `ESP % 16 == 0` ; à l'entrée : `ESP % 16 == 12` (2 arguments empilés après 8 octets de remplissage, puis l'adresse de retour ; vérifié par GDB) | avant `call` : `RSP % 16 == 0` ; à l'entrée : `RSP % 16 == 8` (adresse de retour seule) | assertion du tremplin et test GDB à réécrire, pas à reprendre |
| Registres préservés par l'appelé | EBX, ESI, EDI, EBP | RBX, RBP, R12 à R15 | stubs d'interruption et changements de contexte à réécrire |
| Zone rouge | aucune | 128 octets sous RSP | **interdite en noyau** (`-mno-red-zone`) : une interruption écraserait la zone |
| Retour | EAX (EDX:EAX) | RAX (RDX:RAX) | — |
| Taille de pointeur et de `long` | 32 bits | 64 bits (LP64) | **troncatures `(uint32_t)`** dans le VMM, le PMM et `bootinfo` : audit obligatoire |
| DF à l'appel | 0 (supposé) | 0 (exigé) | inchangé |
| Pile dans les interruptions | CPU : `EIP, CS, EFLAGS` (sans changement de privilège) | CPU : **toujours** `SS, RSP, RFLAGS, CS, RIP`, RSP aligné sur 16 | `struct interrupt_frame` à redéfinir |
| Traces de pile | chaîne EBP | chaîne RBP (`-fno-omit-frame-pointer` conservé) | — |

## 9. Stratégie de validation

### 9.1 Possible **avant** toute implémentation du tremplin

| Test | Type | Moyen |
|---|---|---|
| V1 : modèles de CPU avec et sans `lm`, `nx`, `pae` | environnement | QMP `query-cpu-model-expansion` (fait, §3.7) |
| V2 : chargement d'une image a.out kludge ou d'un conteneur ELF32 (A-1) | expérience jetable, hors dépôt | `qemu -kernel` sur une image minimale |
| V3 : GDB, architecture imposée, symboles ELF64 (H1) | expérience jetable | idem |
| V4 : NMI masquée par le port `0x70` (H3) | expérience jetable, **facultative** : le port `0x70` n'est pas retenu (A-7) | `nmi` du moniteur QEMU |
| V5 : fonction pure de **décision CPUID** (entrée : valeurs EAX/EDX simulées ; sortie : accepté ou refus nommé) | test **hôte**, une fois la fonction autorisée | tableau de vecteurs, y compris les bits réservés et une feuille étendue absente |
| V6 : construction des tables temporaires en **fonction pure** (si elle est écrite en C hôte et testable) | test hôte | page 0 absente, gardes absentes, pas de W+X, alignements |
| V7 : troncatures LP64 (H6) | compilation hôte 64 bits des modules partagés | `-Wconversion` ciblé, tests hôte existants |

V5 et V6 demandent une autorisation d'écrire du code (de test). Ils ne font pas partie de ce document.

### 9.2 Nécessitant le futur tremplin (M64-2)

| # | Cas | Attendu, toujours un diagnostic **nommé** | Positif ou négatif |
|---|---|---|---|
| T-1 | démarrage `qemu64` à 128 MiB | message 64 bits, puis arrêt contrôlé | positif |
| T-2 | démarrage à 16 MiB, 512 MiB, 4 GiB | idem ; carte cohérente | positif |
| T-3 | `-cpu qemu32`, `-cpu qemu64,-lm` | `M64: no long mode`, statut 37, **sans triple fault** | négatif |
| T-4 | `-cpu qemu64,-nx` | refus `M64: no nx` (NX requis, A-4), statut 37, sans triple fault | négatif |
| T-5 | magic falsifié par GDB avant la bascule | refus explicite (port de GDB test 2) | négatif |
| T-6 | MBI falsifiée (adresse 0, chevauchement de l'image, longueur débordante) | refus en C 64 bits, comme `bootinfo_region_ok` | négatif |
| T-7 | tables temporaires invalides, injectées dans l'image de test : bit réservé, PML4 non alignée, page 0 présente | refus nommé `M64: bad page tables` par l'audit T3b, **avant** T5 et T7 ; un #PF ou un triple fault à la place est un **FAIL** | négatif |
| T-8 | pile mal alignée de 8 octets, injectée | `M64: bad stack alignment` (assertion `RSP % 16 == 0` avant `call`) ; dans le cas nominal, GDB relève `RSPMOD16 = 8` à l'entrée du C | négatif et positif |
| T-9 | registres de contrôle mal configurés, injectés : `PAE` absent, `LME` absent, `WP` absent | `M64: lma not set`, ou autotest de registres en échec | négatif |
| T-10 | transition incomplète (saut 64 bits retiré par mutation) | aucun message 64 bits, refus nommé ; un délai dépassé n'est jamais un succès | négatif |
| T-11 | GDB en mode mixte : arrêt dans le tremplin, puis dans le C 64 bits | valeurs attendues des deux côtés, ou **limitation documentée** et test marqué NOT TESTED, jamais un faux PASS | positif et négatif |
| T-12 | GDB en erreur (architecture inadaptée) en mode mixte | FAIL nommé (comme E5 de M64-0) | négatif |
| T-13 | référence i386 | 86/86 cas, GDB 8/8, sous les deux émulateurs ; images i386 identiques octet pour octet | régression |
| T-14 | mutations du tremplin : contrôle LM retiré, WP retiré, page 0 projetée, garde projetée, table temporaire inscriptible, `.text` inscriptible, NXE retiré, alignement de pile retiré, IDT minimale retirée | chacune **détectée** par une assertion nommée (P1 à P5) ; un triple fault n'est pas une détection | contre-tests |
| T-15 | exception provoquée après T11b (`ud2` dans l'image de test) | `M64: exception 6 at RIP …`, statut 37 | positif (diagnostic) |
| T-16 | magic faux **et** MBI à une adresse non projetée | refus « magic » sans #PF : preuve de A-3 | négatif |
| T-17 | structure Multiboot hors de l'identité vérifiée (`cmdline` falsifiée au-delà de 4 MiB, par GDB) | chaîne ignorée et journalisée (V3), **sans lecture** et sans #PF | négatif |
| T-18 | MBI à cheval sur la fin de la zone couverte (`RSI` falsifié à `4 MiB − 40`, par GDB) | refus V1 « invalid multiboot info address », **sans lecture**, sans #PF | négatif |
| T-19 | `cmdline` sans terminateur, finissant exactement à la fin de la zone couverte | chaîne tronquée et signalée (V4), aucune lecture au-delà, sans #PF | négatif |
| T-20 | mutation de liaison : `ALIGN(PAGE_SIZE)` de `.rodata` retiré, d'où une page partagée entre `.text` et `.rodata` | refus par `check_elf` (R4, message nommé) **et** par P1 (« mixed permissions in page N ») | contre-test |
| T-21 | mutation : un objet RW placé dans `.bss.m64_pt` | échec de l'assertion R1 ou de la règle R2 (`check_elf`) | contre-test |
| T-22 | mutation : tables temporaires non alignées sur 4 KiB, ou de taille ≠ 5 pages | échec de l'assertion R1 ; P1 refuse si la liaison passe malgré tout | contre-test |

**Règle :** un triple fault, un délai dépassé ou un arrêt sans message ne sont **jamais** comptés comme une détection (règle des bancs K0.7).

## 11. Critères d'acceptation

### 11.1 M64-1 : construction double, seul jalon d'implémentation envisageable ensuite (sur autorisation)

1. **Images i386 identiques** octet pour octet à la référence, dans un même répertoire : production et test.
2. 86/86 cas QEMU et GDB 8/8 sous les deux émulateurs ; mutations i386 91/91.
3. Squelette `ARCH=x86_64` qui **se lie** : ELF64, `check_elf` ELF64 (R4 : sections alignées et ordonnées ; R5 : pas de W+X ; symboles attendus ; pas de symbole de test en production), avec tests négatifs dont T-20.
4. Drapeaux 64 bits présents et vérifiés : `-mno-red-zone`, `-mgeneral-regs-only`, `-fno-pic`. Modèle de code différé (A-6, D-LAYOUT).
5. **Aucun code exécuté en mode long, aucun tremplin, aucune table de pages** ; aucun format exécutable revendiqué avant A-1.
6. Documentation et CI : deux variantes en `success` au SHA exact ; mutations en précisant si c'est en local ou sur GitHub.

### 11.2 M64-2 : tremplin (autorisation distincte, après V2/V3 et la décision A-1)

1. Critères 11.1 maintenus.
2. Démarrage 64 bits reproductible à 128 MiB et 4 GiB, avec message 64 bits.
3. Refus **nommés** sous `-cpu qemu32`, `-cpu qemu64,-lm` et `-cpu qemu64,-nx` (NX requis, A-4). **Aucun triple fault** dans ces cas ; un triple fault est un FAIL.
4. Contrat de sortie S1 à S11 prouvé, avec valeurs relevées dans le rapport, dont `RSP % 16 == 0` avant `call` et `RSPMOD16 = 8` à l'entrée du C.
5. Tables temporaires : preuves P1, P2 et P4 ; P3 **visée** (Q1), sinon déclarée NOT TESTED, **sans revendication de protection dynamique** ; page 0 et gardes absentes ; pages des tables en RO et XD ; pas de W+X.
6. IDT minimale (T11b) : exception provoquée → message nommé (T-15).
7. Magic et MBI : ordre V0 à V5 (§4.5) respecté ; T-5, T-6, T-16 à T-19 ; la limite de 4 MiB est rapportée comme restriction du prototype.
7 bis. Frontières de permissions : R1 à R5 vérifiées ; T-20 à T-22 refusés par une règle nommée ; aucune protection déclarée avant T7.
8. `check_elf` 64 bits : règles CR0 et INVLPG portées, **avec tests négatifs**.
9. Mutations T-14 toutes détectées par des assertions nommées.
10. Risques résiduels du §5.2 c) **reportés tels quels** ; aucun invariant du §8 déclaré « préservé » sans la preuve de sa colonne.
11. Documentation : `README.md`, `Walkthrough.md`, `Details.md` (mode long, PAE, EFER, GDT64), rapport de jalon.

**Aucune implémentation ne commence sans l'autorisation explicite du développeur.** Le prochain jalon envisageable est **M64-1 seul**.
